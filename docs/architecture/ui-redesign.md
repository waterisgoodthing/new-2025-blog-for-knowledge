# UI 重构方向

> 状态：目标体验原则，待实现；本轮不修改页面、组件或样式。

## 双层信息密度

公开首页与管理后台承担不同任务，可以采用不同信息密度：

- 公开首页面向阅读、回访和轻量学习入口，保持低密度。
- `/manage/**` 面向站点所有者执行学习管理任务，采用高密度工作台。

二者共享品牌色、排版与组件语义，但不强求相同布局密度。

## 公开首页

首页保持现有浅蓝绿色、低密度、青春感和玻璃卡片构图。内容以呼吸感、清晰层级和轻量状态为优先，不改造成学习 Dashboard。

该原则是第一批实现约束：新增学习入口不得顺势把首页改造成 Dashboard。

第一版首页只展示：

- 博客、笔记、错题等公开内容入口。
- 一个轻量“进入学习系统”入口。
- 少量非敏感状态，例如今日是否有学习计划；不展示私有题目、错误详情、OCR/AI 运行或完整统计。

禁止在首页堆叠高密度表格、复杂筛选器、任务队列、模型日志、复习明细或大面积指标卡。

## `/manage/**` 学习工作台

管理端是高密度学习系统工作台，承载科目、知识点、题库、练习、错题、复习、草稿、任务、搜索、统计、AI 和设置。它应提供：

- 稳定的侧边或分组导航。
- 紧凑但可读的表格、筛选器、批量选择和状态标签。
- 来源、草稿、正式数据与失败状态之间的清晰追溯。
- 桌面端高效率与移动端关键任务可完成性。

高密度不等于视觉拥挤：保持一致间距、明确主操作、可访问名称、键盘焦点、空状态、错误恢复和渐进披露。

## 视觉连续性

管理端可降低玻璃效果强度以提升长时间操作的清晰度，但应延续浅蓝绿色品牌线索。公开首页负责情绪与内容发现，管理端负责效率与可验证状态；两者通过色彩、字体、图标和交互反馈保持同一产品感。

## 第一版范围

冻结双层信息密度原则；整理管理导航；为列表、详情、编辑、草稿审核和任务状态定义基础页面模板。暂不进行全站视觉重写、复杂数据大屏或首页 Dashboard 化。
