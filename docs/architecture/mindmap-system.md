# 思维导图系统规范

相关文档：[技术栈](./tech-stack.md)、[渲染系统](./rendering-system.md)、[前端结构](./frontend-structure.md)、[图标系统](./icon-system.md)。

## 1. 思维导图系统目标

为层级知识内容提供统一、可缩放、可降级的可视化入口，同时保持 Markdown 源可读、可迁移，不与流程图职责混合。

## 2. 目标技术栈

思维导图使用 Markmap，通过 `MindMapBlock` 统一封装，并由 ` ```markmap ` 代码块触发。Markmap 只是渲染能力，不成为业务数据存储格式。

## 3. Markdown 触发方式

````markdown
```markmap
# 计算机网络
## 网络层
### IP 地址
### 路由选择
## 传输层
### TCP
### UDP
```
````

普通 Markdown 标题不会自动变为思维导图；只有显式 `markmap` fenced block 才触发。

## 4. MindMapBlock 组件职责

- 只在客户端初始化 Markmap。
- 把受控的 markmap Markdown 渲染为 SVG。
- 管理组件实例、重绘和卸载清理。
- 负责容器尺寸、缩放、滚动与 fit 行为。
- 负责加载与错误降级。
- 不处理 Mermaid，也不处理普通代码块。

## 5. 与 Mermaid 的边界

Markmap 用于层级知识结构、大纲和章节脉络；Mermaid 用于流程、时序、状态和依赖关系。不要用 Mermaid 画大纲，也不要用 Markmap 画流程。

## 6. 使用场景

- 课程章节脉络
- 考研知识框架
- 错题知识点归因
- 复习大纲
- 项目架构树

如果内容重点是步骤先后、条件分支、调用顺序或状态转换，应改用 Mermaid。

## 7. 容器与交互规范

- 提供稳定最小高度，并设置合理最大高度，避免首屏无限扩张。
- 小屏允许容器内滚动；页面本身不得被超宽 SVG 撑破。
- 支持缩放、拖动、fit/recenter，并为按钮提供可访问名称。
- 初始化时测量真实容器；容器变化时节流重绘。
- 遵守 reduced-motion，键盘操作和焦点样式不得缺失。
- 节点文本、链接与样式必须经过白名单处理。

## 8. 错误降级

解析或渲染失败时仅影响当前块，显示简洁说明和“查看原始内容”的折叠入口。不得展示堆栈、内部版本、未经处理的 `error.message` 或不安全 HTML。JavaScript 不可用时至少保留可读源内容。

## 9. 迁移策略

1. 在统一 `RichText` 中加入显式 block detection。
2. 建立客户端 `MindMapBlock`、安全边界与固定容器。
3. 用正常、超深、超宽、空内容和错误语法样例验证。
4. 先在 admin preview 验证，再开放公开渲染。
5. 旧思维导图实现归零后再清理。

本轮只定义目标方案，不盘点现有内容、不安装 Markmap、不创建组件。

## 10. 禁止事项

- 不把所有 Markdown 标题自动转换为思维导图。
- 不用 Markmap 表达流程、时序或状态机。
- 不与 Mermaid 共用职责模糊的渲染组件。
- 不在服务端访问浏览器 DOM 初始化 Markmap。
- 不允许无限高度、无滚动或撑破页面的 SVG。
- 不直接显示解析器错误或执行不可信 HTML。
