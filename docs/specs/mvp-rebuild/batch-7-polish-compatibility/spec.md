# Batch 7：体验收口、旧路由兼容、数据质量

## 目标

在不大规模重构旧公开系统的前提下，将第一版收口为可本地试运行状态。

## 背景

核心链路完成后仍需处理旧入口、公开读取隔离、空状态、失败状态、基础校验和数据
质量。该批只做收口，不借机扩展新业务或云部署。

## 任务范围

1. 旧 `/write-mistake` 入口重定向或提示迁移。
2. 保留 `/write-note`，不强行破坏原流程。
3. 保证旧 `/mistakes` 公共页不被管理端状态或操作污染。
4. 首页学习轻卡链接到 `/manage/drafts` 和 `/manage/review`。
5. 补齐 empty、loading 和 error state。
6. 补齐基础表单校验。
7. 为删除或归档增加明确确认。
8. 检查并修复本 MVP 范围内的明显死链接。
9. 增加本地试运行说明。
10. 做数据质量检查并记录，不自动迁移或删除旧数据。

## 允许修改范围

- 本批对应 workflow 与本地试运行文档。
- 上述旧入口、首页轻卡和已完成 `/manage` 页面的小范围兼容与状态修复。
- 直接相关共享组件、API 错误呈现、表单校验和测试。
- 本批范围内的链接、导航和验证材料。

具体文件必须在本批 tasks 中列明并获用户批准。

## 禁止事项

- 不大规模重构旧公开页。
- 不删除旧数据或自动迁移旧错题。
- 不做复杂兼容层。
- 不引入云部署。
- 不封闭 `/mistakes`、`/notes`、`/notes/[slug]`、`/blog` 或 `/blog/[slug]`。
- 不把权限重构与编辑器重构合并成不可审查的大 diff。
- 不顺手实现 AI、OCR、BKT、完整练习或统计。

## 涉及页面

- `/`
- `/write-mistake`
- `/write-note`
- `/mistakes`
- `/notes/[slug]`
- 已完成的 `/manage/*` MVP 页面

## 涉及数据表

原则上不新增表。只检查 Batch 2–5 已批准数据的完整性、约束和历史兼容性；
任何迁移需求必须单独列出并重新审批。

## 验收标准

1. 旧公开页面可正常读取且没有管理端操作泄漏。
2. `/manage` 主链路可本地使用。
3. MVP 范围内没有明显死链接。
4. 空、加载、失败状态清楚且不会被伪装为成功。
5. 基础表单校验和危险操作确认有效。
6. 本地试运行说明可由新环境执行。
7. 旧数据未被删除或未经批准自动迁移。
8. 权限、前后端合同、数据质量和真实浏览器验收均有记录。

## 非目标

公开站重做、复杂兼容层、自动历史数据迁移、云部署及任何后续高级能力。

## 完成后 handoff 要求

记录兼容改动、数据质量结果、本地试运行步骤、完整验收证据、剩余风险和下一轮需求；
本批结束仍需用户明确确认，不能由代理自行宣称整个项目闭环。
