# 需求文档：MVP 本地试运行验收

## 背景

Batch 0–7 开发实现阶段已进入有条件通过状态，未发现 P0 阻塞项。为避免继续扩大开发范围，
下一阶段只进行本地试运行验收，用真实但少量、人工改写的样例数据验证 MVP 第一版主链路是否可用。

## 用户角色

- 站点所有者 / 管理员：在本地环境登录管理后台，录入样例数据并完成复习与附件操作。
- 审查者：根据试运行记录判断是否存在阻塞项、非阻塞问题和下一轮需求。

## 核心问题

1. 当前已有实现主要由开发阶段验证支撑，仍缺少真实样例数据贯穿全链路的验收记录。
2. 新表与新管理工作区需要在本地真实操作下验证关联关系、状态流转和附件读写。
3. LeetCode 相关练习只可作为本地少量测试素材，必须避免公开发布、批量采集或版权越界。
4. 发现问题后只记录，不自动修复，避免把试运行阶段重新变成开发阶段。

## 功能需求

### REQ-LT-01 本地试运行 checklist

- 输入：Batch 0–7 当前实现、本地环境、管理员会话、少量人工样例。
- 处理：按链路逐项检查环境、权限、数据创建、状态转换、附件上传/关联/读取。
- 输出：可勾选的本地试运行 checklist。
- 失败处理：失败项进入 `issues.md`，不自动修改业务代码。
- 验收标准：checklist 覆盖完整目标链路和禁止范围。

### REQ-LT-02 样例数据计划

- 输入：用户批准的 LeetCode 相关练习方向，建议 3–5 题。
- 处理：只设计人工改写数据结构、字段模板、来源标注和公开边界。
- 输出：`sample-data-plan.md`。
- 失败处理：若某题不适合改写或录入，标记为跳过，不补抓题库。
- 验收标准：不包含原题大段复制，不包含爬取/API/导入计划。

### REQ-LT-03 试跑记录模板

- 输入：试运行中的真实操作步骤、API/页面反馈、数据 ID、截图路径或日志摘要。
- 处理：按样例和链路节点记录实际结果。
- 输出：`trial-record.md`。
- 失败处理：无法执行的步骤标记为 blocked 或 failed，并引用问题编号。
- 验收标准：能区分 pass、partial、fail、blocked、not run。

### REQ-LT-04 问题记录表

- 输入：本地试运行发现的问题。
- 处理：记录复现步骤、影响范围、严重程度、是否阻塞 MVP 本地验收、建议归属批次。
- 输出：`issues.md`。
- 失败处理：问题只记录，不自动修复；除非用户另行批准。
- 验收标准：所有失败项均能追溯到 checklist 或 trial record。

### REQ-LT-05 本地真实试跑

- 输入：已批准的执行任务清单、本地 PostgreSQL、前后端服务、管理员会话、3 条人工转述样例和一个无敏感信息的测试附件。
- 处理：依次跑通 subject → knowledge point → question draft → question → mistake draft → mistake → review item → review record → attachment upload/link/read。
- 输出：完成的 `checklist.md`、`trial-record.md`、`validation.md` 和必要时的 `issues.md`。
- 失败处理：遇到需要修改业务代码、迁移、脚本或配置才能继续的阻塞项时停止对应链路，只记录证据，不修复。
- 验收标准：每个已执行节点均有页面、API、数据库记录或日志之一作为可复核证据；未执行节点不得标记为通过。

### REQ-LT-06 私有与公开边界复核

- 输入：本地试跑产生的样例对象和附件。
- 处理：检查公开 `/blog`、`/notes`、`/mistakes` 及公开附件访问边界。
- 输出：公开边界的实际结果与证据。
- 失败处理：若发现样例或附件公开泄露，立即停止试跑并登记 P0 问题。
- 验收标准：本地私有样例未出现在公开列表，未登录用户不能执行管理写入、复习或上传操作。

### REQ-LT-07 临时管理员解阻复跑

- 输入：用户于 2026-07-04 对本地临时管理员账密的明确授权、项目既有 `create-temp-admin` / `disable-temp-admin` CLI。
- 处理：生成一次性本地管理员密码、建立密码会话、复跑 P0-09 至 P0-12，并在结束后禁用临时账号。
- 输出：不含密码的认证、主链路与清理证据。
- 失败处理：密码不写入仓库或报告；任一步失败时停止后续写入，记录问题，并仍尝试禁用临时账号。
- 验收标准：临时密码仅存在于权限受限的临时文件；`AUTH_BYPASS` 保持关闭；复跑后临时账号被禁用。

## 非功能需求

- 安全：不得依赖 `AUTH_BYPASS` 作为验收通过方式；不得公开私有学习样例。
- 合规：LeetCode 相关内容只作本地少量改写样例，不公开、不批量、不自动化抓取。
- 可审查：记录必须区分已验证、未验证、失败、阻塞和跳过。
- 可维护：问题记录应能转化为下一轮需求，但本轮不直接修复。

## 明确边界

本轮不做：

- 业务代码修改。
- 数据库迁移。
- 导入脚本。
- 批量题库功能。
- AI Gateway、OCR、BKT、完整练习系统。
- 对象存储、云部署。
- LeetCode 抓取、API 接入或公开发布。
- 自动修复试运行发现的问题。

## 总体验收标准

本 workflow 只有在执行阶段获批且以下条件满足后才算完成：

1. checklist 已覆盖目标完整链路。
2. sample-data-plan 明确 3–5 题人工改写策略和版权边界。
3. trial-record 能记录每个样例的链路执行结果。
4. issues 能承接所有失败和疑问。
5. 至少 3 条人工转述样例已按批准范围执行，或所有未执行项均有明确阻塞证据。
6. 主链路各节点都有实际结果和可复核证据。
7. 所有失败项均进入 `issues.md`，并转化为剩余风险或明确归档。
8. 没有修改业务代码、脚本、迁移、公开内容或部署配置。

## 项目验收与演示准备需求

### REQ-DEMO-01 验收摘要

- 输出：一页式项目验收摘要，说明已通过链路、条件项、数据状态和范围外事项。
- 标准：结论必须区分 `pass`、`conditional pass`、`blocked` 与 `not run`，不得把条件项写成完全通过。

### REQ-DEMO-02 演示脚本

- 输出：按 10–15 分钟组织的演示步骤、页面、讲解重点和失败恢复说明。
- 标准：覆盖 Public Read、Private Manage、核心学习闭环和 Closure Evidence；不得要求 AI/OCR、云部署或新功能。

### REQ-DEMO-03 现场执行边界

- 默认只做只读演示，不新增数据库数据。
- 若需现场写入、登录或重新试跑，必须重新批准对应任务，并继续使用本地私有数据、现有认证和既有接口。
- 不使用 `AUTH_BYPASS`，不展示真实密码、token、私钥或敏感附件。

## DEMO-ISSUE-001 修复需求

### REQ-FIX-01 公开错题入口恢复

- `/mistakes` 必须作为公开读取页可匿名访问。
- 不得将 `/mistakes` 重定向到 `/manage/mistakes`。
- `/mistakes/review` 仍必须保持私有保护。

### REQ-FIX-02 回归证据

- 增加或调整测试，证明 `/mistakes` 的公开 route contract 和 `/mistakes/review` 的私有 route contract 同时成立。
- 重新进行 P0-15 只读浏览器演示。
- 发现其他问题只记录，不顺手修复。

### REQ-FIX-03 数据与范围边界

- 不新增或修改数据库数据。
- 不创建 migration，不修改 schema，不改变后端 API 契约。
- 不进入部署、AI/OCR/Capture、Search、Analytics、Practice 或 BKT。

## LT-ISSUE-002 修复需求

### REQ-AUTH-01 禁用账号登录错误码

- 禁用临时管理员使用原密码登录必须返回 401 `Invalid credentials`。
- 不得返回 500 或暴露 bcrypt/内部异常信息。

### REQ-AUTH-02 密码校验健壮性

- 无效、禁用或 malformed password hash 必须被视为凭据不匹配。
- 合法密码校验行为保持不变。

### REQ-AUTH-03 验收边界

- 增加后端回归测试并运行相关权限/认证测试。
- 不创建用户、不修改现有账号数据、不使用 `AUTH_BYPASS`。
- 不进入 Passkey、认证架构重构、迁移、部署或其他条件项修复。
