# Personal Learning System V2 递进执行计划

状态：`I0–I6 COMPLETE / PASS / I7 APPROVAL REQUIRED`

## 1. 执行方法

本计划不按“大阶段全部完成”推进，而是按单一、可回滚、可验收的增量推进：

```text
批准一个增量 → 实施该增量 → 记录验证与风险 → 用户验收 → 再批准下一个增量
```

每个增量必须满足：

1. 只解决一个用户可感知的能力或一个前置安全门槛。
2. 只修改该能力必要的前后端、契约、迁移和测试；不顺带重构邻近领域。
3. 完成后立即在 `tasks.md` 勾选对应条目，并在 `validation.md` 记录代码、API、浏览器、权限和恢复证据。
4. 验收失败、范围扩大、需要 schema/迁移、需要删除或需要生产操作时，立即停止并重新请求批准。
5. 未经单独批准，不得把“通过本地验证”扩大为部署、迁移、切换或旧系统停写。

## 3. 每个增量的交付模板

开始任何 I1～I11 前，都要在本工作区记录以下内容：

```text
目标：本增量唯一要交付的能力
范围：允许修改的页面、API、schema、迁移和测试
不做：明确排除的相邻能力
前置：已批准任务、依赖证据、数据/备份状态
验收：代码检查、API 契约、浏览器路径、匿名/管理员权限、恢复或回滚证据
退出：PASS / PARTIAL / BLOCKED，以及下一步是否需要新的批准
```

## 4. 关键批准关口

| 关口 | 必须获得的用户批准 |
|---|---|
| G0 | 批准 I0 的统一方案与任务清单，才可进入任何实现或恢复核验 |
| G1 | 批准每个 I1～I9 的具体增量，才可修改该增量的代码、契约或测试 |
| G2 | 批准 I10，且 Migration Gate 已达到 `DRY_RUN_READY`，才可向隔离目标写入 |
| G3 | 单独批准 I11 的影子迁移；权威切换、旧写停用和归档还需单独批准 |
| G4 | 批准 I12 的部署资格审查；审查通过也不自动授权发布 |
