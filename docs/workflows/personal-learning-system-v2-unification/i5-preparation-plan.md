## 目标

为 I5 建立可单独审批的最小增量：管理员私有资料、首页显示偏好（欢迎语/品牌/时区等必要字段）和响应式/键盘验收闭环。必须明确哪些内容属于公开站点设置，哪些属于管理员私有设置，避免把私有资料注入公开页面或继续复用不匹配的 legacy 配置契约。

## 准备阶段

1. 盘点现有 site-settings、manage settings、认证和用户模型，区分公开读取与管理员写入。
2. 形成 I5 设计/需求/任务清单，明确最小字段、API、前端入口、权限、空态、失败态和不做事项。
3. 检查是否需要 schema/model/migration；任何 schema 或数据写入只记录为待审批事项。
4. 记录响应式三尺寸与键盘验收路径，但不提前执行 I5 浏览器验收。
5. 用户已批准任务清单；I5-01 至 I5-10 已逐项验证并已在 tasks/validation 中记录。

## 硬停止条件

- 无法证明私有设置与公开 `site-settings` 的数据边界。
- 需要新增 migration、修改生产配置、生产数据写入或真实账户操作。
- 发现公开页面会读取管理员私有资料，或管理员写入缺少 `get_current_admin`。
- 任何 I5 任务依赖未完成的 I4 closure-fix 或改变 I4 已归档契约。
