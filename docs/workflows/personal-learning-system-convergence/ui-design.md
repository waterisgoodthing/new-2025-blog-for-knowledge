# Personal Learning System Convergence UI 设计规范

> 状态：目标态 UI 合同，审美与交互方向已确认，尚未实施。
> 基线：`refactor/baseline` @ `4a954ea`；整理日期：2026-09-04。
> 范围：私有 `/manage/**` 学习工作台及其认证入口。公开阅读页面继续保持现有低密度风格，除非具名任务明确纳入。

## 1. 目的与效力

本文把已选定的 UI 方向整理为可实施、可验收的规范，是 convergence workflow 的 UI 细节事实源。

文档冲突时按以下顺序处理：

1. 当前源码、后端契约、测试和明确的安全要求；
2. 本 workflow 的 `requirements.md` 与 `design.md`；
3. 本文定义的视觉、交互、动效、响应式和状态行为；
4. `docs/architecture/ui-redesign.md` 与 `docs/architecture/frontend-structure.md`；
5. 历史 UI workflow 仅作背景参考。

本文不授权整站重写、增加依赖、修改认证、修改 schema、执行 migration、部署、commit 或 push。30 天 convergence 计划只实现分配到已批准 PR 的 UI 切片；其余目标态 UI 必须另行拆任务和审批。

## 2. 核心体验

私有工作台是一张由独立悬浮模块组成的个人学习桌面。第一眼可以分散、跳跃、不对称，但必须由隐藏网格、稳定层级和保存位置维持秩序。

核心构图是 **乱中有序**：

- 每项功能占据一个独立方框；
- 模块之间不连成连续面板；
- 页面不再用一个装饰性大容器包住所有模块；
- 重要模块更大，辅助工具更小并有意错位；
- 桌面端保留约 20%-25% 空画布；
- 隐藏网格约束边缘、间距和落点，但不呈现机械宫格；
- 主内容使用饱满大圆角，数据与工具模块使用较小圆角；
- 半透明表面保留原背景，任何情况下都优先保证内容对比度。

公开首页继续维持现有轻盈、个人化、低密度的入口形态，不改造成私有学习 Dashboard。

## 3. 视觉基础

### 3.1 品牌色

保留当前运行时品牌色：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--color-brand` | `#35bfab` | 主品牌、焦点、正向进度 |
| `--color-brand-secondary` | `#1fc9e7` | 渐变终点、选中强调 |
| `brand-gradient` | `#35bfab -> #1fc9e7` | 主按钮、进度、选中态 |
| `brand-gradient-dark` | 深青绿 -> 深青蓝 | 全屏专注背景 |
| `danger` | 满足对比度的红色 | 冲突、破坏性操作、失败 |

渐变不能铺满普通页面。只用于主操作、进度、选中指示、扩展起点和关键过渡粒子。正文、输入框、表格和次级控件保持中性色。

选中态使用浅色品牌渐变、可见边框和非颜色指示器。渐变边框必须低透明度。阴影使用很淡的青绿/青蓝色，不制造厚重灰色光晕。

### 3.2 背景

- 保留原 UI 的移动模糊色块背景；
- 空闲和会话查询时缓慢漂移；
- 登录框展开时冻结，保持认证界面稳定；
- 登录成功时随内容从中心向外扩展；
- 夜间跟随系统偏好降低背景亮度，本阶段不另造完整深色主题；
- 不增加与功能无关的静态渐变圆球；过渡点和 OCR 碎片属于功能性动效。

### 3.3 表面与几何

| 元素 | 几何规则 |
| --- | --- |
| 主内容模块 | 大圆角或近似 squircle，目标半径 28-40px |
| 数据/工具模块 | 12-16px 较小圆角 |
| 主按钮 | 14-16px 圆角，原品牌渐变填充 |
| 短弹窗 | 28-32px 饱满圆角 |
| 悬浮抽屉 | 距屏幕边缘 20-24px |
| Popover | 紧凑圆角，从触发点展开 |
| Toast | 底部居中的大圆角方框 |

表面采用半透明白色、克制的 blur 和清晰边界。不得在一组独立模块外再套装饰卡片。普通列表使用分隔行，只有重点记录可脱离列表成为独立框。

### 3.4 字体

| 内容 | 字体 |
| --- | --- |
| 正文内的大标题 | LXGW WenKai Screen |
| UI 短标题、关键数字 | Smiley Sans |
| 英文展示文字 | Averia Gruesa Libre |
| 正文、表单、按钮、列表、元数据 | 系统无衬线字体栈 |
| 代码 | 现有等宽字体栈 |

规则：

- 短标题与正文大标题是两个不同字段，可以不同；
- 短标题服务列表、导航和检索，使用 Smiley Sans；
- 正文内大标题属于内容，使用 LXGW WenKai Screen；
- 英文展示文本可使用 Averia，长篇混排回退到系统字体；
- 字号不直接随 viewport 宽度缩放；
- 字间距不得为负值；
- 新字体实施前必须核对许可证、加载方式、fallback、中文子集和布局偏移。当前只有 Averia 已有项目 token，其他字体仍是目标依赖，不能写成已安装。

### 3.5 图标与控件

- 界面图标使用 `lucide-react`；
- 主要图标可使用克制的双色品牌处理，次级图标保持线性；
- 熟悉操作优先用图标按钮，并提供 accessible name 和 tooltip；
- 输入框留在所属表单模块内，不把每个字段拆成无上下文的悬浮框；
- 筛选器集中在独立工具框内，模式切换优先使用 segmented control；
- 模式使用 segmented control，多选使用 checkbox，二元设置使用 toggle，数值使用 slider、stepper 或输入框；
- 最小点击/触摸目标为 `44px x 44px`；
- 破坏性操作使用红色描边按钮，并进入确认 Modal。

## 4. 布局系统

### 4.1 桌面工作台

- 默认中等密度；
- 模块大小由任务重要性决定；
- 主导航是左上角独立方框；
- 中央首要模块是 `今日先做`；
- 其他模块按已保存位置落在隐藏网格上，并保持有意的不对称；
- Hover 时模块上浮 4px，同时增强边框和阴影，不改变占位尺寸；
- 切换页面或视图时，旧模块淡出，新模块从不同方向错峰出现；
- 简短任务在原模块内展开；需要多步骤和独立 URL 的复杂任务进入对应路由；
- 每个模块独立承担 loading、empty、error、retry、busy 和 success 状态。

### 4.2 用户自定义布局

- 系统提供默认落点，用户可进入布局模式拖动并保存；
- 布局模式下模块略微缩小并显示明确拖动手柄；
- 首次进入空工作台时，中央显示一个模块库方框；
- 用户批量勾选模块，点击 `完成` 后统一展开；
- 已选模块从中央向外爆开，按默认位置依次落位；
- 后续仍通过模块库增减，不强制固定六个模块。

### 4.3 保存与冲突

- 移动后立即写入本地，再在后台同步到账户；
- 以单个 widget 为同步单位，并使用明确的 layout revision 或等效版本标识；
- 如果同一 widget 在本地修改后 5 秒内检测到远端修改，其状态框报红并显示冲突；
- 服务器版本获胜，本地模块退回服务器位置，并明确显示降级处理，不能静默宣称成功；
- 5 秒冲突窗口结束后恢复正常同步；
- 因为是单用户产品，文案表述为“另一会话/设备”，不虚构协作者。

当前 convergence 后端尚未定义布局 revision 和同步 API。账户同步必须另开契约任务；在此之前可明确交付“仅本地保存”，但不得伪装成跨设备同步。

## 5. 会话查询与登录

### 5.1 认证不变量

浏览器不读取 token。进入私有地址时，通过带 `credentials: include` 的 `getMe()` 或批准的会话接口查询 HttpOnly `admin_session`。`AuthGate` 只负责界面和导航保护，`get_current_admin` 仍是后端授权边界。

### 5.2 查询状态

打开私有地址后：

1. 只显示完整背景；
2. 在正中央显示加载动效；
3. 加载动效最少保留 600ms，避免画面闪烁；
4. 完整动效只用于首次进入私有区域或明确的会话重新验证，不在内部路由切换时重复。

加载动效由六个大小不同的渐变方块碎片构成，分布在两条反向旋转轨道：

- 内圈约 1.8 秒一周；
- 外圈约 3.2 秒一周；
- 两圈有轻微呼吸，但不得改变周围布局。

可参考 Magic UI Orbiting Circles 的运动组织，实施时优先使用项目已有 `motion` 和本地组件，不为复制示例增加运行时依赖。

### 5.3 查询结果

| 结果 | 行为 |
| --- | --- |
| 已认证 | 方块汇聚成一点，执行径向展开并逐步显示工作台 |
| `401/403` | 方块汇聚成小方框，再扩大为登录模块 |
| 网络/超时/`5xx` | 自动重试一次，仍失败则显示可重试的小错误框，不显示登录表单 |

认证成功使用约 850ms 的由内向外展开。模块按固定种子的伪随机顺序出现，既有自然感，也能稳定测试。

### 5.4 登录模块

- 桌面宽度 400px；
- 移动端最大宽度 `calc(100vw - 32px)`；
- 居中展示，不占满全屏；
- 周围可散落辅助小框；
- 主登录框使用大圆角，辅助框混合不同圆角；
- Passkey 与密码是并列入口；
- Passkey 点击后直接开始；
- 密码表单在登录框内向下展开；
- 登录元素从不同方向错峰淡入。

失败状态：

- 凭据错误时登录框在约 240ms 内左右 +/-6px 抖动三次；
- 顶部显示简短错误摘要，同时在对应字段显示具体错误；
- 通过 live region 只播报一次；
- throttling 延迟属于后端事实，前端不得伪造倒计时。

成功状态：

- 登录框先缩成小方框，再汇成一点；
- 从该点执行类似宇宙大爆炸的径向展开；
- 可参考 Magic UI Ripple/Particles，但粒子必须有边界、测试可重复，并能在 reduced motion 下完全移除；
- 登录成功固定进入 `今日学习`，`今日先做` 是最主要模块。

## 6. 今日工作台

### 6.1 `今日先做`

中央最大模块命名为 `今日先做`，只展示：

- 一个推荐任务；
- 一条简短推荐理由；
- 一个主操作按钮。

推荐优先级：

1. 已生成且有效的 AI 推荐；
2. 基于 canonical 复习/练习优先级的确定性 fallback。

UTC+8 自然日内首次点击私有网址并通过认证后，如果当天没有结果，可启动一次推荐生成。生成期间显示缓存推荐或确定性 fallback。即使是单用户，服务端也必须保证同一天幂等。AI 失败时 `今日先做` 静默使用 fallback，另一个 AI 状态模块显示失败与重试。

该每日 AI 契约扩展了核心推荐行为，不能仅凭 R09 UI 任务实施；后端工作必须按 R11 治理另行审批。

### 6.2 进入专注模式

- 点击主按钮后，`今日先做` 在原位扩大；
- 主按钮是几何展开起点；
- 模块扩大为覆盖整个工作台的全屏专注面；
- 其他模块向外散开并淡出；
- 控件以独立小框悬浮在屏幕边缘，不增加连续工具栏；
- 专注面使用原青绿到青蓝渐变的深色版本；
- 退出严格反向播放：专注面收回主按钮，原模块回到保存位置。

## 7. 复习与 Re-answer

### 7.1 业务顺序

UI 必须遵循：

`Mistake -> Re-answer -> Evaluation -> Rating Recommendation -> User Confirm -> ReviewRecord`

提交答案不等于提交复习评分。

### 7.2 空间动效

1. 题目框最初占据主要全屏区域；
2. 提交答案后，题目框缩小到左侧；
3. 中央和右侧各出现一个渐变小点；
4. 中央小点爆开形成答案/评估框；
5. 右侧小点稍晚爆开形成操作/评分框。

桌面目标宽度约为题目 30%、答案 42%、操作 22%，间距不完全一致但受隐藏网格约束。

每个会话的第一题可播放完整约 950ms：

- 题目缩小 320ms；
- 小点出现 120ms；
- 答案框展开 280ms；
- 操作框比答案框晚约 80ms 开始；
- 最后稳定约 150ms。

后续题目压缩至约 420ms。答案内部各段以约 60ms 间隔依次出现。

### 7.3 评分

- 每个评分是纵向排列的独立小框；
- 每个点击目标至少 44px 高；
- 键盘快捷键与真实评分值一致；
- 推荐评分与用户最终确认必须视觉可区分。

此前视觉选择提到“五个评分框、按键 1-5”，但当前 convergence 契约和 API 使用 `0-5` 六档。除非另行批准修改领域契约，UI 必须完整显示六个评分并支持键盘 `0-5`；视觉偏好不能吞掉一个业务值。

### 7.4 推进、撤销与完成

- 评分确认后，当前内容向左滑出，下一题从右侧进入；
- 底部居中显示可撤销 Toast，持续 8 秒；
- 撤销必须真正逆转已持久化的 Review 操作，或明确报告失败，不能只改画面；
- 本轮结束时，内容汇聚成一点，再爆开形成数量、正确率、薄弱点和返回入口等独立总结框。

## 8. 写作工作台

### 8.1 构图

- 正文编辑框是最大独立模块；
- 短标题、属性、AI、保存状态、发布分别散落为独立方框；
- 不设置包住全部编辑功能的大卡片，也不设置常驻连续工具栏；
- 正文编辑框默认占据大部分画布。

正文获得焦点时向中心扩大，外围工具框向画布边缘退开；失焦后按原路径复位。

### 8.2 标题

- 短标题用于列表、导航和检索；
- 正文大标题属于文章内容；
- 两者可以不同；
- 首次创建时可根据正文大标题提出短标题建议，最终由用户控制。

### 8.3 格式工具

- 不显示常驻格式工具栏；
- 选中文字后，在选区附近显示小型圆角上下文工具框；
- 选区消失后收拢，除非焦点已经进入工具框；
- 碰撞处理后仍须位于 viewport 内，且尽量不遮盖选中文字；
- 支持的格式操作必须保留键盘方式。

### 8.4 保存状态

保存状态是正文框外侧的独立小框：

| 状态 | 表现 |
| --- | --- |
| editing | 中性、稳定 |
| saving | 透明度呼吸 |
| saved | 青绿/青蓝成功色，随后收小 |
| offline/local | 明确标注仅本地 |
| failed | 红色错误与重试 |
| conflict | 靠近正文框、边界报红、说明 server-wins 降级结果 |

状态切换不得清空输入。只有 canonical 持久化成功后才能显示 saved。

### 8.5 属性

- 默认只显示一个属性摘要框；
- 点击后，摘要框分裂成标签、分类、状态、可见性等独立小框；
- 保存或点击空白处后重新聚合；
- 存在焦点或校验错误时不得提前聚合。

### 8.6 AI 辅助

- 选中文字后，AI 入口与上下文格式工具框同时出现；
- 点击后在选区附近展开独立结果框，但不得覆盖原文；
- 原文与 AI 结果并排显示，并按段落标记差异；
- 每段可独立接受或拒绝；
- AI 结果不得静默覆盖正文；
- 关闭时必须明确保留原文，并按用户动作丢弃或保留临时建议。

该交互遵循 R11：polish 在用户明确保存前是 transient preview；生成持久化学习数据必须经过 AiRun 治理和人工确认。

### 8.7 发布

- 发布模块平时缩成低调的小方框；
- 标题、正文和必要属性满足条件后扩大并点亮；
- 点击后进入确认 Modal，满足条件不代表自动发布；
- 发布失败必须保留编辑内容并呈现真实服务端状态。

## 9. 快速采集与 OCR

### 9.1 入口

`快速采集` 是工作台常驻独立模块，支持：

- 粘贴图片；
- 拖入图片文件；
- 移动端拍照。

不支持的文件必须在上传前拒绝，并给出具体、可恢复的说明。

### 9.2 识别动效

- 原图保留在采集框中；
- 识别文字以多个碎片框陆续出现；
- 完成后，碎片聚合成可编辑候选框；
- 动效只表达 pipeline 进度，不能暗示内容已经正确。

### 9.3 候选确认

在字段适用时，分别生成标题、正文、题目、答案和标签候选框。用户直接在每个候选框内修改并逐项确认。未经确认的 OCR/AI 内容不得覆盖 canonical 结构化数据。

系统推荐结果类型，用户确认将其转为笔记、题目或错题草稿；推荐不能直接触发转换。

### 9.4 失败与重复

- 失败碎片报红，原图继续保留；
- 显示失败分类、安全错误详情、重试和手动录入；
- 后端支持幂等时，重试复用原 capture identity；
- 发现疑似重复时，打开独立对比框，提供 `覆盖`、`合并`、`新建`；
- 禁止自动合并；
- 离开页面后允许后台继续识别，由独立状态模块展示进度与结果。

R10 仍是事实边界：受控 OCR gate 未通过时，入口必须显式禁用或标明不可用。好看的动效不能掩盖失败 pipeline。

## 10. 弹层与反馈

### 10.1 职责

| Primitive | 用途 |
| --- | --- |
| Modal | 确认、短表单 |
| Drawer | 长设置、移动端长表单 |
| Popover | 与触发点关联的快速选择 |
| Toast | 短反馈、撤销 |

- 同时只打开一个主要弹层；仅允许 Drawer 内再打开已支持的确认 Modal；
- 短 Modal 居中；
- 移动端长表单使用底部 Drawer；
- 桌面 Drawer 距 viewport 边缘 20-24px；
- Popover 从触发点缩放展开，碰撞调整后仍保持锚定关系。

### 10.2 弹窗动效

- Modal 使用 28-32px 饱满圆角；
- 进入时落入画布，并带极轻微回弹；
- 遮罩为低透明度深色，并使用约 6px blur；
- 关闭时反向缩小并淡出，约 160ms；
- 校验和异步状态变化不能使 Modal 外框跳动。

### 10.3 Toast、提醒、声音和触觉

- Toast 是底部居中的大圆角方框；
- 同时只显示一个，其余排队；
- 撤销 Toast 持续 8 秒，普通反馈使用标准短时长；
- 每日提醒默认显示站内模块，浏览器系统通知由用户主动开启；
- 声音默认关闭，可选择开启完成、错误和爆炸过渡音效；
- 移动端触觉反馈仅用于成功、错误和完成。

## 11. 移动端

### 11.1 工作台

- 主模块单列排列；
- 宽度允许时，小模块可组成错落双列；
- 顺序按任务优先级，不照搬桌面坐标；
- 右下角悬浮导航按钮展开独立导航框；
- 长按可进入布局模式，同时必须提供可见按钮作为等效入口；
- 模块库使用独立全屏页面。

### 11.2 复习

题目、答案/评估和操作区依次全屏切换，不把桌面三框强行压缩到一行。

### 11.3 编辑器

- 正文占据全屏；
- 标题、属性和 AI 从底部 Drawer 展开；
- 软件键盘出现时重新排布，确保当前输入框及其错误可见；
- 横屏时在空间允许的情况下重组为双栏或三栏。

### 11.4 导航与安全区

- 提供可见返回按钮，同时可支持右滑返回；
- 手势只能增强，不能成为唯一入口；
- 固定控件必须考虑 `env(safe-area-inset-*)`；
- Drawer、Toast、悬浮按钮和软键盘不得相互遮挡。

## 12. 统一动效系统

### 12.1 时长档位

| 时长 | 用途 |
| --- | --- |
| 160ms | 退出、淡出、小控件响应 |
| 240ms | 登录抖动、Popover、紧凑位移 |
| 320ms | 模块缩放或主要空间步骤 |
| 420ms | 后续复习题的压缩过渡 |
| 850-950ms | 少量入场、完整展开、会话首次编排 |

能落入上述档位时，不为单个组件任意增加新时长。

### 12.2 曲线与中断

- 方框的位置和缩放使用克制的 spring；
- 透明度与颜色使用平滑 cubic easing；
- 新操作从当前视觉状态直接平滑转向新状态；
- 不为播放完动效而锁死界面；
- 先确定布局，再动画 transform 和 opacity，避免持续动画布局尺寸。

### 12.3 Reduced motion

在 `prefers-reduced-motion: reduce` 下：

- 移除背景漂移、粒子、回弹、大范围缩放位移和抖动；
- 保留短暂淡入淡出和直接状态替换；
- 保留结果、焦点移动、live announcement 和撤销时限；
- 不得要求用户通过动效理解状态或进度。

### 12.4 性能降级

低性能设备或实测掉帧时，自动减少粒子、blur 和背景漂移。所有装饰动效关闭后，功能仍必须完整可用。长任务使用真实进度或明确的不确定状态，不运行高耗能装饰循环。

## 13. 数据与异步状态

每个路由和独立加载模块均须定义：

| 状态 | 要求 |
| --- | --- |
| loading | 稳定的代表性结构，以轻微透明度呼吸表示进行中，不用 0 冒充未知值 |
| empty | 简短含义和一个有效下一步 |
| error | 真实失败、安全详情、可重试时提供 retry |
| partial | 成功模块继续可用，失败模块明确标识 |
| busy | 禁用触发控件，不阻塞无关模块 |
| success | 权威操作成功后才显示 |
| offline/local | 与服务端已保存明确区分 |
| conflict | 明确胜出版本和恢复结果 |

路由级状态使用 App Router `loading.tsx` 和 `error.tsx`，数据面板使用 convergence 的 `AsyncStatePanel` 契约。API 失败绝不能显示成空数据。可恢复错误不得清空输入和本地草稿。

## 14. 无障碍

- 所有功能均可由键盘完成；
- 焦点顺序按任务顺序，而不是散落模块的视觉坐标；
- 可见焦点使用高对比实心青色双环；
- 颜色不是唯一状态信号；
- Modal/Drawer 打开后合理移动焦点，在阻塞场景约束焦点，安全时支持 Escape，隔离背景，并在关闭后恢复到触发控件；
- 动态错误和完成信息使用合适且不重复的 live announcement；
- 长中文、英文单词、公式、代码和错误信息须换行或滚动，不能溢出模块；
- 浏览器缩放到 200% 后仍可完成核心任务；
- 选区工具必须可由键盘操作，不破坏原生文本行为；
- 依赖认证的控件在会话解析前预留稳定几何，不得闪现。

## 15. 实现边界

- 保持 `page/component -> feature hook 或 local action -> src/lib/api/* -> backend API`；
- 优先复用已安装的 `motion`、`lucide-react`、`sonner`、SWR、Zustand 和 dnd-kit；
- Magic UI 与 Motion Primitives 是交互参考，不是已批准依赖；优先用项目现有能力复刻行为；
- Overlay、状态、动效、模块等共享 primitive 只有在至少两个真实 consumer 需要时才进入共享目录；
- public/admin API client 保持分离；
- 受保护控件仍须经过后端授权；
- 旧写作路由必须完成 redirect、内部链接迁移、观察、删除的批准顺序后才能移除。

## 16. 浏览器验收合同

UI 完成必须提供真实浏览器证据。jsdom 可验证逻辑，但不能证明布局、焦点、动效、Canvas/SVG、导航或安全区行为。

### 16.1 视口

至少验证：

- 桌面：1440x900；
- 紧凑桌面/平板：1024x768；
- 移动端：390x844；
- 窄移动端：320x568；
- 一个移动横屏视口。

### 16.2 必测场景

1. 会话查询：已登录、未登录、网络/`5xx` 重试、reduced motion；
2. 登录：Passkey、密码展开、错误凭据、throttling、成功展开；
3. 空工作台：模块批量选择、统一爆开、拖动、刷新持久化、冲突降级；
4. `今日先做`：AI 成功、确定性 fallback、AI 失败、全屏进入和反向退出；
5. 复习：首题完整动效、后续压缩动效、六档评分、真实撤销、完成总结；
6. 编辑器：选区工具、聚焦扩大、保存状态、属性分裂/聚合、AI 段落对比、发布确认；
7. OCR：支持的上传/粘贴/拍照、碎片动效、候选编辑、失败、重试、重复对比、后台继续；
8. 弹层：焦点进入/约束/恢复、Escape、外部交互、滚动锁、Toast 排队、键盘、安全区；
9. 响应式：无重叠、裁切、布局跳动、不可访问控件或文字溢出。

### 16.3 动效证据

- 主要 morph 截取开始、中间和结束画面；
- 记录变化前后的 box geometry，起点和终点必须与触发模块一致；
- 验证动效中断和反向路径；
- reduced motion 下确认无粒子、回弹、抖动和大范围位移；
- 对全屏与粒子序列保留浏览器性能证据；出现明显长帧或阻塞输入即验收失败。
