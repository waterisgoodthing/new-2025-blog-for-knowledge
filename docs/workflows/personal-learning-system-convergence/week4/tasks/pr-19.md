## Objective

Finalize AI governance by documenting the polish classification decision and ensuring all AI calls that produce canonical learning data record proper `target_type` and `target_id` linkage in AiRun.

## Scope

**In scope:**
- Document polish classification (transient preview, no forced linkage)
- Audit current AI call sites producing canonical entities
- Verify target linkage for modification-type calls
- Verify backfill contract for creation-type calls
- Test AiRun rows have correct target references

**Out of scope:**
- Rewriting AI prompts or changing generation quality
- Adding new AI features (auto-tagging, summaries, trends)
- Event sourcing or complex audit trails beyond AiRun
- Prompt versioning or A/B testing

## Background (W4-D05)

**Polish classification decision:**  
Polish (`polish_stream`) is a **transient preview** — streaming output, no `target_id` in request, result only persists when user explicitly saves. This does not require forced AiRun linkage. If polish later becomes direct-persist (auto-save without user confirmation), it must first enter the audit chain.

**Enforcement scope:**  
AI calls that produce **canonical learning entities** must record `target_type` and `target_id`:

- **Modification-type**: acting on existing Note/Question/Mistake/Capture → write `target_id` at call time
- **Creation-type**: generating new entity → backfill `target_id` after user confirmation creates entity; if user abandons suggestion, `target_id` remains NULL (valid state)

**Classification of current features:**
- Capture recognition → produces Capture entity → **must link**
- Capture draft/question generation → produces MistakeDraft/Question → **must link**
- Polish → transient preview → **exempt**
- Diagram generation → if purely visual aid, transient; if saved as artifact, must link
