# 个人知识与博客系统整体演进 — 需求文档

> 版本: 1.0
> 日期: 2026-06-02
> 关联设计文档: `docs/personal-knowledge-system-design.md`

## 1. 项目背景

### 1.1 系统定位

本项目面向单一用户长期使用，不按多用户 SaaS 或普通静态博客扩展。系统目标是成为个人知识工作台，统一承载：

- 公开博客。
- 私有笔记。
- 错题记录。
- AI 辅助写作。
- AI 辅助整理。
- 复习计划与知识点归总。

当前系统已有 Next.js 前端、FastAPI 后端、PostgreSQL、`Note(type=note|blog|mistake)` 模型、错题复习、AI 分析和 GitHub sync。后续需求重点不是堆叠新页面，而是让系统形成稳定、清晰、可长期维护的个人知识闭环。

### 1.2 当前主要问题

| 问题 | 影响 |
|---|---|
| 博客、笔记、错题仍存在旧静态系统和后端系统的迁移中间态 | 数据真源不够清楚，后续扩展容易分裂 |
| AI 能力分散，缺少知识库级管理助手 | 无法自动发现缺标签、缺归类、错题薄弱点等问题 |
| 写笔记 AI 入口不够体系化 | AI 不能稳定基于选区、全文和光标上下文辅助写作 |
| 编辑体验仍偏 Markdown 手动输入 | 图表、对比图、思维导图、颜色、高亮、模板不够直观 |
| 按钮和工具入口可理解性不足 | 用户不知道按钮作用，功能学习成本高 |
| 模板依赖隐藏命令体验 | 不符合“看得懂、点得到”的个人工作台需求 |
| 错题 AI 解析内容偏少 | 不能充分支持理解错误、归纳知识点和举一反三 |
| 复习规划不够清晰 | 用户缺少今日、本周、薄弱点维度的学习计划 |
| 缺少文件夹和拖拽排序 | 信息架构不够有空间感，长期积累后难整理 |

### 1.3 总体目标

系统后续应满足：

- 数据以 PostgreSQL 中的知识内容为主，公开导出和 GitHub sync 作为出口。
- 用户可以在符合当前 UI 气质的界面中写作、整理、复习和发布。
- AI 分成两个角色：知识库 AI 管家和编辑器 AI 写作助手。
- 编辑器支持更多可视化内容块，但短期仍保留 Markdown 作为主要存储格式。
- 错题模块从“记录”升级为“解析、归纳、复习、规划”。
- 文件夹、标签、分类、科目共同构成清晰的信息组织方式。

## 2. 范围

### 2.1 本需求覆盖范围

- AI 知识库管家。
- AI 写作助手。
- 笔记编辑器体验升级。
- 图表、对比块、思维导图、颜色、高亮、模板。
- 文件夹和拖拽排序。
- 按钮、tooltip、模板入口和操作反馈。
- 错题 AI 解析升级。
- 复习规划和归总。
- 数据真源、公开边界和 UI 约束。

### 2.2 本阶段暂不覆盖

- 多用户团队协作。
- SaaS 级权限模型。
- 完整块编辑器替换 Markdown。
- 营销型首页改版。
- 复杂商业化后台。
- 全量重构现有 UI。

## 3. 用户故事

### US-1: AI 管理知识库

作为唯一用户，我希望 AI 能分析我的所有笔记、错题和博客，告诉我哪些内容需要整理、哪些错题属于同一知识点、哪些笔记缺少标签或文件夹，这样我不需要手动维护所有归类。

### US-2: AI 辅助写笔记

作为写作者，我希望在写笔记时，AI 能基于当前选中文本、光标位置和全文帮我续写、改写、扩写、总结、生成标题、生成图表或生成思维导图。

### US-3: 可理解的编辑体验

作为用户，我希望按钮和模板入口都是可见、可理解的，而不是必须记忆 `/` 指令或猜图标含义。

### US-4: 多样化笔记表达

作为学习者，我希望笔记里能插入图表、对比图、思维导图、表格、颜色、高亮和重点块，这样知识结构更清楚。

### US-5: 文件夹和排序

作为长期使用者，我希望能用文件夹组织内容，并通过拖拽调整文件夹和笔记顺序，这样知识库越积越多时仍然可控。

### US-6: 更完整的错题解析

作为学习者，我希望 AI 对错题输出更完整的解析，包括错误原因、正确步骤、知识点、相似易错点、举一反三和变式题。

### US-7: 清晰复习规划

作为学习者，我希望系统能告诉我今天该复习什么、本周薄弱点是什么、哪些知识点反复错，以及下一步怎么安排。

## 4. 功能需求

### FR-1: 数据真源与公开边界

**优先级**: P0

**描述**: 系统应明确 PostgreSQL 中的后端知识模型为主要数据源，公开页面和 GitHub sync 只作为公开展示、导出或备份出口。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-1.1 | `Note(type=blog|note|mistake)` 作为核心内容模型 | 博客、笔记、错题均可通过后端 API 查询 |
| FR-1.2 | `note` 默认私有 | 未明确公开的普通笔记不进入 RSS、sitemap、公开博客列表 |
| FR-1.3 | `mistake` 默认私有 | 错题不进入公开导出 |
| FR-1.4 | `blog` 满足 `status=published && hidden=false` 才公开 | RSS、sitemap、博客列表只包含公开博客 |
| FR-1.5 | GitHub sync 不作为主数据源 | sync 行为在 UI 和文档中明确为发布/备份 |

### FR-2: AI 知识库管家

**优先级**: P1

**描述**: 提供面向整个知识库的 AI 管家，帮助分析、整理、规划和归类内容。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-2.1 | AI 管家可分析最近笔记、博客、错题 | 能输出最近内容摘要和整理建议 |
| FR-2.2 | AI 管家可发现缺少标签/分类/文件夹的内容 | 输出具体内容列表和建议标签/文件夹 |
| FR-2.3 | AI 管家可推荐关联笔记和关联错题 | 每条建议包含被关联内容和理由 |
| FR-2.4 | AI 管家可总结薄弱知识点 | 输出按科目或知识点聚合的薄弱项 |
| FR-2.5 | AI 管家可生成每日/每周复习规划 | 输出可执行复习列表 |
| FR-2.6 | AI 管家默认只建议，不直接修改 | 批量修改必须由用户确认 |
| FR-2.7 | AI 管家入口符合当前 UI | 以卡片、侧栏或管理面板形式展示，不使用突兀聊天大页作为唯一入口 |

### FR-3: AI 写作助手

**优先级**: P1

**描述**: 在写笔记/编辑笔记页面提供面向当前内容的 AI 写作助手。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-3.1 | AI 写作助手可读取当前全文上下文 | 发起 AI 操作时带上标题、类型、全文或必要上下文 |
| FR-3.2 | 支持选区操作 | 选中文本后可改写、扩写、总结、提炼要点 |
| FR-3.3 | 支持光标插入 | AI 结果可插入到当前光标位置 |
| FR-3.4 | 支持替换选区 | 用户可明确选择替换当前选区 |
| FR-3.5 | 支持生成标题、摘要、目录、标签 | 输出可直接应用到表单或插入正文 |
| FR-3.6 | 支持生成图表、对比块、思维导图 | 输出符合编辑器可渲染的 Markdown/block 语法 |
| FR-3.7 | 面板可折叠 | 桌面端右侧面板可收起，移动端使用抽屉 |

### FR-4: 编辑器工具栏与按钮体验

**优先级**: P0

**描述**: 改善当前按钮可理解性，形成清晰分组的工具栏。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-4.1 | 重要操作使用图标 + 文字 | 保存、预览、发布、删除、模板、AI 等不能只有抽象图标 |
| FR-4.2 | 图标按钮必须有 tooltip 和 `aria-label` | 鼠标悬停可看到功能说明，屏幕阅读器可识别 |
| FR-4.3 | 工具栏按功能分组 | 至少包含保存/预览、插入、AI、格式、模板 |
| FR-4.4 | 危险操作有明确样式和确认 | 删除、批量删除、公开发布需要明显区分 |
| FR-4.5 | 操作后有反馈 | 保存、上传、AI 生成、删除等均有 toast 或状态反馈 |
| FR-4.6 | 视觉符合当前 UI | 使用半透明卡片、圆角、品牌色、轻量动效 |

### FR-5: 模板可见化

**优先级**: P0

**描述**: 模板不再主要依赖 `/` 指令，提供可见、可读、可点击的模板入口。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-5.1 | 工具栏提供“模板”按钮 | 用户无需输入 `/` 即可打开模板面板 |
| FR-5.2 | 模板面板展示名称和说明 | 每个模板有一句用途描述 |
| FR-5.3 | 支持课堂笔记模板 | 包含核心概念、例题、总结 |
| FR-5.4 | 支持错题解析模板 | 包含错误原因、正确思路、知识点、复习提醒 |
| FR-5.5 | 支持读书笔记模板 | 包含观点、摘录、个人想法 |
| FR-5.6 | 支持项目复盘模板 | 包含目标、过程、问题、改进 |
| FR-5.7 | `/` 指令保留为高级快捷入口 | 不作为模板的唯一入口 |

### FR-6: 内容块与多样化笔记表达

**优先级**: P1

**描述**: 笔记支持更多可视化内容块，同时短期继续以 Markdown 为主要存储格式。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-6.1 | 支持 Mermaid 图表插入和预览 | 流程图、时序图等可渲染 |
| FR-6.2 | 支持思维导图插入和预览 | Mermaid mindmap 或自定义 mindmap block 可渲染 |
| FR-6.3 | 支持对比块 | 可展示左右对比或多项对比 |
| FR-6.4 | 支持表格模板 | 用户可一键插入表格结构 |
| FR-6.5 | 支持字体颜色或重点色 | 通过受控色板选择，避免任意颜色污染 UI |
| FR-6.6 | 支持高亮 | 文本可标记重点 |
| FR-6.7 | 内容块移动端不溢出 | 图表、表格、对比块在移动端可滚动或自适应 |
| FR-6.8 | 内容块符合当前文章样式 | 不引入明显割裂的视觉风格 |

### FR-7: 文件夹与拖拽排序

**优先级**: P2

**描述**: 建立文件夹系统和拖拽排序能力，形成个人知识空间。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-7.1 | 支持文件夹树 | 文件夹可有父子层级 |
| FR-7.2 | 支持收件箱 | 未归档内容默认显示在收件箱 |
| FR-7.3 | 笔记可绑定文件夹 | 内容可移动到指定文件夹 |
| FR-7.4 | 支持拖拽笔记到文件夹 | 拖拽后刷新仍保持归属 |
| FR-7.5 | 支持同级文件夹排序 | 拖拽排序后刷新仍保持顺序 |
| FR-7.6 | 支持文件夹内笔记排序 | 同一文件夹内可调整笔记顺序 |
| FR-7.7 | 移动端提供非拖拽替代操作 | 通过菜单/抽屉也能移动和排序 |
| FR-7.8 | 标签与文件夹职责清晰 | 文件夹负责归档，标签负责横向关联 |

### FR-8: 错题 AI 解析升级

**优先级**: P0

**描述**: 错题 AI 输出更完整、更结构化，用于理解错误和归纳知识点。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-8.1 | 输出题目识别 | AI 明确识别原题内容 |
| FR-8.2 | 输出我的错误点 | 指出错误答案或错误思路 |
| FR-8.3 | 输出正确答案 | 给出明确正确答案 |
| FR-8.4 | 输出完整解题步骤 | 不只给结论，要有步骤 |
| FR-8.5 | 输出关键转折点 | 标出解题中最关键的一步 |
| FR-8.6 | 输出为什么会错 | 分析认知误区或常见误解 |
| FR-8.7 | 输出涉及知识点 | 可用于标签、科目、关联笔记 |
| FR-8.8 | 输出相似易错点 | 帮助预防同类错误 |
| FR-8.9 | 输出举一反三 | 给出变式思路或变式题 |
| FR-8.10 | 输出复习建议 | 说明下次复习重点 |
| FR-8.11 | 输出结构可进入一等字段 | 不只作为纯 Markdown 文本保存 |

### FR-9: 复习规划与归总

**优先级**: P0

**描述**: 复习模块应清晰展示今日、本周和长期薄弱点。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-9.1 | 显示今日复习队列 | 用户进入错题页能看到今日待复习数量和入口 |
| FR-9.2 | 显示本周复习规划 | 输出本周建议复习科目/知识点 |
| FR-9.3 | 显示薄弱知识点 | 按错误频率、复习表现或 AI 归纳展示 |
| FR-9.4 | 按科目统计 | 展示各科目总题数、待复习、薄弱项 |
| FR-9.5 | 按知识点统计 | 展示高频错误知识点 |
| FR-9.6 | 复习完成后显示总结 | 本次复习题数、掌握变化、下一步建议 |
| FR-9.7 | 支持 AI 周总结 | AI 输出本周主要问题和下周建议 |

### FR-10: 笔记、错题、博客管理体验

**优先级**: P1

**描述**: 管理面板和列表页应支持更清晰的内容整理与批量操作。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-10.1 | 管理页可按类型筛选 | `blog`、`note`、`mistake` 可快速过滤 |
| FR-10.2 | 管理页可按文件夹筛选 | 文件夹系统上线后可用 |
| FR-10.3 | 管理页可按标签/科目筛选 | 支持定位知识主题 |
| FR-10.4 | 批量操作前显示影响范围 | 批量删除、移动、改标签前列出数量和目标 |
| FR-10.5 | AI 整理建议可进入管理页 | 管理页显示待整理项和建议操作 |

### FR-11: 首页个人工作台入口

**优先级**: P2

**描述**: 首页在保留当前卡片布局的前提下，增加个人今日入口。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-11.1 | 首页显示今日待复习 | 以当前卡片风格展示数量和入口 |
| FR-11.2 | 首页显示最近笔记或草稿 | 快速回到最近工作内容 |
| FR-11.3 | 首页显示 AI 今日建议 | 简短展示整理或复习建议 |
| FR-11.4 | 不改成营销首页 | 首屏仍保持个人空间气质 |

### FR-12: 路由跳转与页面落点一致性

**优先级**: P0

**描述**: 当前结构审查发现，博客、笔记、错题、管理面板和编辑页之间存在部分跳转语义不统一的问题。系统应明确每类内容的详情入口、编辑入口、保存后落点和后端 API 注册状态。

推荐默认规则：

```text
blog 详情入口: /blog/{slug}
blog 编辑入口: /write/{slug}
note 详情入口: /notes/{slug}
note 编辑入口: /write-note/{slug}
mistake 详情入口: /mistakes/{slug} 或明确继续复用 /notes/{slug}
mistake 编辑入口: /write-note/{slug} 或 /write-mistake/{slug}
```

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-12.1 | 明确 `blog` 的唯一主要详情入口 | 博客列表、首页最新文章、管理面板中的博客标题跳转策略一致，优先进入 `/blog/{slug}` |
| FR-12.2 | 明确 `note` 的详情入口 | 普通笔记列表和管理面板中的普通笔记标题进入 `/notes/{slug}` |
| FR-12.3 | 明确 `mistake` 的详情入口 | 要么新增 `/mistakes/{slug}` 错题学习页，要么在文档和 UI 中明确错题详情复用 `/notes/{slug}` |
| FR-12.4 | 管理面板跳转按内容类型分流 | `blog` 查看进入 `/blog/{slug}`，`note` 查看进入 `/notes/{slug}`，`mistake` 查看进入错题详情入口 |
| FR-12.5 | 编辑入口按内容类型分流 | `blog` 编辑进入 `/write/{slug}`，`note` 和 `mistake` 编辑进入对应笔记/错题编辑页 |
| FR-12.6 | 保存后落点一致 | 新建/更新后跳转到该内容的主要详情页或明确停留在编辑页并提供“查看”入口 |
| FR-12.7 | 取消操作落点一致 | 新建取消返回来源页或首页，编辑取消返回该内容主要详情页 |
| FR-12.8 | 删除后落点一致 | 删除 `blog` 后回 `/blog`，删除 `note` 后回 `/notes`，删除 `mistake` 后回 `/mistakes` |
| FR-12.9 | 后端 taxonomy router 必须注册 | `backend/main.py` 必须 include `categories.router` 和 `subjects.router`，使 `/api/categories`、`/api/subjects` 与前端 `src/lib/api/meta.ts` 对齐 |
| FR-12.10 | 写笔记和编辑笔记的分类/科目候选可用 | 打开 `/write-note` 和 `/write-note/{slug}` 时，分类下拉和科目 datalist 能正常加载 |
| FR-12.11 | 静态内容页继续标注为静态配置线 | `/share`、`/projects`、`/pictures`、`/bloggers`、`/snippets`、`/about` 的 JSON 数据源和保存方式应在系统地图中保持明确 |

当前审查确认的主要跳转关系：

```text
首页导航:
  /blog
  /notes
  /mistakes
  /about
  /share
  /bloggers

首页卡片:
  写文章 -> /write
  最新文章 -> /blog/{slug}
  今日推荐 -> recommendation.target 或 /notes
  随机推荐 -> /share
  图片卡 -> /pictures
  头像 -> /live2d
  时钟 -> /clock

主列表:
  /blog -> /blog/{slug}
  /notes -> /notes/{slug}
  /mistakes -> /notes/{slug}（当前复用）
  /manage -> /notes/{slug}（当前统一查看，待按类型分流）
```

## 5. 非功能需求

### NFR-1: UI 一致性

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR-1.1 | 保留当前半透明卡片风格 | 新组件使用 `bg-white/60`、`backdrop-blur`、边框和圆角体系 |
| NFR-1.2 | 保留轻量动效 | 使用 `motion/react` 的小幅动效，不做夸张动画 |
| NFR-1.3 | 操作界面不营销化 | 工作台页面保持密集但清晰 |
| NFR-1.4 | 移动端可用 | 工具栏、AI 面板、文件夹侧栏有移动端形态 |

### NFR-2: 可访问性

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR-2.1 | 图标按钮有 accessible name | 所有 icon-only 按钮有 `aria-label` |
| NFR-2.2 | 图片有 alt | 有意义图片必须提供 alt |
| NFR-2.3 | 键盘可操作 | 主要弹窗、工具栏、确认框可键盘操作 |
| NFR-2.4 | 不禁用用户缩放 | 移动端可正常缩放 |

### NFR-3: 数据安全与可靠性

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR-3.1 | 图片有持久化策略 | 错题图片和笔记图片不会因后端重建丢失 |
| NFR-3.2 | 私有内容不进入公开导出 | 隐藏、草稿、普通笔记、错题不出现在公开文件中 |
| NFR-3.3 | 删除和批量修改可确认 | 高风险操作前必须确认 |
| NFR-3.4 | AI 批量整理先建议后执行 | 不自动大规模改数据 |
| NFR-3.5 | 数据库变更有迁移 | 模型变更必须有 Alembic migration |

### NFR-4: 性能

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR-4.1 | Mermaid 等重库懒加载 | 只在需要时加载 |
| NFR-4.2 | AI 调用有 loading 状态 | 用户知道正在处理 |
| NFR-4.3 | 大图和图表可缩放/滚动 | 不撑破文章布局 |
| NFR-4.4 | 列表分页或虚拟化 | 内容增长后列表仍可用 |

### NFR-5: 工程约束

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR-5.1 | 前端 API 走 `src/lib/api/*` | 组件不直接散落 fetch 调用 |
| NFR-5.2 | 后端 router 保持 thin | 复杂逻辑进入 service |
| NFR-5.3 | TypeScript 类型同步后端 schema | 新字段前后端同步 |
| NFR-5.4 | 不引入大型依赖解决小问题 | 拖拽、图表等依赖需评估 |
| NFR-5.5 | 变更按域收敛 | 避免一边改错题一边重构无关博客 |

## 7. 阶段规划

### 阶段一：交互可理解性

**优先级**: 最高

范围：

- 路由跳转和保存后落点一致性修复。
- `categories` / `subjects` 后端 router 注册修复。
- 工具栏重组。
- 按钮补文字、tooltip、`aria-label`。
- 模板面板可见化。
- 危险操作反馈和确认。

完成标准：

- 博客、笔记、错题、管理面板跳转规则清晰一致。
- 写笔记页和编辑笔记页能正常加载分类/科目候选。
- 用户不用读文档也能理解主要按钮。
- 模板可以通过明确按钮打开。
- 重要操作不只依赖图标。

### 阶段二：错题 AI 和复习规划

**优先级**: 最高

范围：

- 错题 AI prompt 和结构化输出升级。
- 错题详情页分区升级。
- 今日/本周/薄弱点复习规划卡片。
- 复习完成总结。

完成标准：

- AI 输出包含错误原因、完整步骤、知识点、变式题、复习建议。
- 用户能清楚知道今天和本周该复习什么。

### 阶段三：AI 写作助手

**优先级**: 高

范围：

- 右侧 AI 写作面板。
- 选区改写/扩写/总结。
- 光标插入/替换选区。
- 生成标题、摘要、目录、标签。
- 生成图表、对比块、思维导图。

完成标准：

- AI 结果可直接进入编辑器。
- 用户能选择插入或替换。
- 移动端有可用抽屉。

### 阶段四：内容块能力

**优先级**: 高

范围：

- Mermaid 图表模板。
- 思维导图模板。
- 对比块。
- 表格模板。
- 颜色和高亮。
- 复习卡片块。

完成标准：

- 内容块可插入、可预览、可在详情页渲染。
- 移动端不溢出。

### 阶段五：文件夹和拖拽排序

**优先级**: 中

范围：

- Folder 模型、schema、router、migration。
- 知识库侧栏。
- 拖拽移动笔记。
- 文件夹和笔记排序。
- 收件箱。

完成标准：

- 刷新后归属和排序保持。
- 移动端有非拖拽替代方式。

### 阶段六：AI 知识库管家

**优先级**: 中

范围：

- 内容体检。
- 标签/文件夹建议。
- 关联笔记建议。
- 每周学习总结。
- 批量整理建议确认执行。

完成标准：

- AI 输出具体内容、原因和建议动作。
- 用户确认后才执行批量修改。

## 8. 验收总标准

系统整体演进达到以下状态时视为需求完成：

- 博客、笔记、错题有清晰统一的数据来源和公开边界。
- 博客、笔记、错题、管理面板之间的查看、编辑、保存、取消、删除跳转规则一致。
- `/api/categories` 和 `/api/subjects` 与前端分类/科目候选功能稳定对齐。
- 写笔记时，用户能直观看到保存、预览、插入、AI、格式、模板等入口。
- 模板不需要依赖隐藏命令。
- AI 可以分别完成当前写作辅助和全库整理建议。
- 笔记可插入图表、对比块、思维导图、表格、颜色和高亮。
- 错题 AI 输出足够完整，能支持理解、归纳和复习。
- 复习页能展示今日、本周、薄弱点和复习总结。
- 文件夹和拖拽排序让长期内容可组织。
- 新功能仍符合当前柔和卡片式 UI，而不是变成陌生产品。

## 9. 待确认事项

- 图片持久化最终使用对象存储、持久卷，还是 GitHub/private backup。
- `blog` 是否允许私有草稿和私有预览。
- `blog` 在管理面板中点击标题时是否必须进入 `/blog/{slug}`，还是允许进入通用 `/notes/{slug}`。
- `mistake` 是否新增独立详情路由 `/mistakes/{slug}` 和编辑路由 `/write-mistake/{slug}`。
- 新建/更新博客后是否自动跳转到 `/blog/{slug}`，还是停留编辑页并显示“查看文章”。
- 文件夹是否允许嵌套层级超过 2 层。
- 错题知识点是否独立建模，还是继续使用 tags/subjects。
- AI 管家是否允许自动执行低风险整理动作，例如补摘要或推荐标签。
- 复习计划是否只使用 SM-2，还是结合 AI 周计划和个人目标。
