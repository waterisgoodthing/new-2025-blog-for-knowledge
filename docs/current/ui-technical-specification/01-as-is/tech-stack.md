## 技术选型决策（ADR）

### ADR-001：选择 Tailwind CSS 4

**日期**：2024-XX-XX

**决策**：使用 Tailwind CSS 4 作为样式框架

**理由**：
- 统一样式管理
- 工具类优先（utility-first）
- 与 Next.js 集成良好
- 性能优化（按需生成）

**替代方案**：
- CSS Modules：样式隔离好，但需要更多手写 CSS
- Styled Components：运行时性能开销

**后果**：
- ✅ 开发效率高
- ✅ 样式一致性好
- ⚠️ 学习曲线（团队需要熟悉工具类）

---

### ADR-002：选择 Motion（Framer Motion）

**日期**：2024-XX-XX

**决策**：使用 Motion 作为动画库

**理由**：
- 声明式 API
- 强大的动画能力
- 与 React 集成良好
- 活跃维护

**替代方案**：
- CSS Transitions：能力有限
- GSAP：学习曲线陡峭

**后果**：
- ✅ 动画流畅
- ⚠️ 包体积较大（需 Code Splitting）

---

### ADR-003：选择 UI V2 架构

**日期**：2026-09-20

**决策**：建立独立的 UI V2 组件系统，与 Legacy 并存

**理由**：
- 渐进式迁移（不破坏现有页面）
- 命名空间隔离（`--uiv2-*`）
- 完整 Token 系统

**替代方案**：
- 直接重构 Legacy 组件：风险高，回归成本大
- 使用第三方 UI 库（Ant Design/MUI）：定制成本高

**后果**：
- ✅ 风险可控
- ✅ 可并行开发
- ⚠️ 暂时存在两套组件（计划 Phase 4 废弃 Legacy）
