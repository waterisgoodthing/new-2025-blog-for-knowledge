# I6 需求

状态：`IMPLEMENTED / VERIFIED (2026-07-24)`

## 功能需求

### REQ-I6-01 私有单文件采集

- 使用者：管理员。
- 输入：一张允许的图片文件和可选的错误上下文。
- 处理：后端校验身份、MIME、大小、文件名、存储路径和私有状态，再创建 Capture 引用；不复制业务主数据。
- 输出：私有 Attachment 与 `uploaded` Capture。
- 失败：匿名/失效会话返回 401；非法文件返回 4xx；失败不得留下可读的临时对象或 Capture。
- 验收：HTTP 权限、路径安全、清理和 Capture 来源关联测试通过。

### REQ-I6-02 单图识别状态机

- 输入：`uploaded` Capture。
- 处理：读取已验证附件，执行单图识别适配器，记录阶段、尝试次数、时间和安全结果。
- 输出：成功进入 `recognized` 并保存识别文本；失败进入 `failed` 并保存有限错误码。
- 失败：附件缺失、空输入、无 provider、超时、provider 错误和解析错误均不可写入正式草稿/学习对象。
- 验收：每类失败有独立测试，并核对正式对象计数不变。

### REQ-I6-03 可人工修正的草稿生成

- 输入：识别文本、管理员补充上下文和可选学科。
- 处理：生成候选题面、解析、错因和知识点建议；所有输出先写 Capture 草稿区，人工输入可覆盖自动结果。
- 输出：成功进入 `ready`；失败保持安全 `failed`，允许人工补齐后恢复。
- 失败：空识别文本、schema 不合法和 provider 失败不得写入 `mistake_drafts`、`mistakes` 或 `review_items`。
- 验收：fake 成功、失败零污染、人工修正恢复测试通过。

### REQ-I6-04 草稿审核与人工闸门

- 输入：管理员对类型化 Question/Mistake Draft 的查看、编辑、拒绝或确认操作及版本号。
- 处理：校验状态、版本、学科/知识点和来源仍有效；编辑递增版本并回到待处理状态；拒绝不可转换。
- 输出：审计上可追溯的 pending/needs_fix/rejected/converted 结果，确认后才生成正式对象。
- 失败：过期版本返回冲突；拒绝草稿转换返回冲突；来源失效或字段不完整返回可修正错误。
- 验收：HTTP 与 service 测试覆盖状态机、版本冲突、拒绝、确认和来源保留。

### REQ-I6-05 幂等与审计

- 输入：同一 Capture 或 Draft 的重复识别、草稿、转换请求。
- 处理：重复转换返回既有目标；重复执行不创建第二个正式对象；保存来源附件、来源 Capture、创建者、版本、目标和安全时间字段。
- 输出：稳定的既有结果与可核对的操作链。
- 失败：并发/重复请求发生冲突时 fail-closed，不静默覆盖或生成重复对象。
- 验收：重复请求、版本冲突、来源链和数据库唯一约束测试通过。

## 非功能需求

- 权限：所有上传、读取私有内容、Capture、Draft 和转换 API 均为管理员边界；不新增公开附件或草稿读取。
- 数据：PostgreSQL 仍是正式事实来源；未确认 AI/OCR 结果只能存在 Capture/Draft。
- 安全：错误响应不得泄露本地路径、原始 provider 错误、私有文本或密钥。
- 可恢复性：阶段失败可重试或人工修正；不使用不可逆删除清理失败对象。
- 可维护性：复用已有 Attachment/Capture/Draft service 和 contracts；路由保持薄。

## 不做

- 批量 OCR、PDF 多页流水线、真实 AI 成功验收、后台队列/Redis、文件夹树、全文搜索、多人/RBAC、公开发布、迁移切换和部署。
