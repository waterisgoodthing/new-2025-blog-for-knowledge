## 2026-07-20 暂停记录

已从 I1 的数据库 dump 将 revision `020` 恢复到临时 PostgreSQL 实例，并以临时附件根目录启动后端；测试管理员仅存在于该隔离数据库。前端使用独立的 `2026` 端口，后端使用独立的 `8001` 端口；两者均未复用现有的 `2025` / `8000` 日常服务。

浏览器访问 `http://127.0.0.1:2026/manage` 后，前端向隔离后端请求 `GET /api/auth/me`，得到预期的 `401 Not authenticated`。但页面在五秒后仍只显示“验证中…”，未出现密码登录表单，浏览器控制台没有页面错误。这阻止了正常密码登录和后续真实浏览器写入链路验证。

后续只读诊断确认：后端健康端点正常；带 `Origin: http://127.0.0.1:2026` 的匿名请求已返回对应的 CORS 允许头；页面上下文直接请求相同的 `/api/auth/me` 也会立刻收到 `401`。因此未发现后端、数据库 readiness 或 CORS 阻塞。新建隔离浏览器会话后，管理页仍无 API 请求且停留在“验证中…”，表明页面的客户端水合或 `useEffect`/SWR 状态流未正常推进。

## 2026-07-20 重试与验收结论

先前“认证页面阻塞”的结论不成立于独立生产构建：独立 Git worktree 的生产前端、独立 PostgreSQL revision `020` 和独立附件根目录中，匿名 `GET /api/auth/me` 得到 `401` 后正常显示密码登录表单；测试管理员经浏览器密码登录后可进入工作区。开发服务器的复现属于运行时/构建环境差异，不构成认证源码修复依据。

结论：I2 已完成本轮验证，但 C-01 至 C-03 均未通过完整验收。后续需要一个新批准的产品实现增量，补齐 Attempt、从 Attempt 转 Mistake，以及启用采集后 AI/OCR 失败的手工回退；这些不在 I2 或 I2-R 的授权范围内。

临时前端、后端、PostgreSQL 和自动化浏览器会话已停止；隔离数据库、附件根目录、独立 worktree 和测试管理员已整体移入系统废纸篓，现有日常服务未受影响。
