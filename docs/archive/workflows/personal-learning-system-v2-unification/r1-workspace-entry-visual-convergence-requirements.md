# R1 管理工作区入口与视觉收敛需求

状态：`APPROVED / EXECUTED / CLOSED`

## 功能需求

### R1-REQ-01 唯一管理工作区

- `/manage` 继续作为管理员登录入口。
- `/manage/dashboard` 继续作为唯一 canonical workspace。
- 不得同时维护 `/workspace` 的独立数据编排、导航和子路由。

### R1-REQ-02 权限边界不变

- `/manage/**` 继续由共享 `AuthGate` 提供页面级保护。
- 后端写操作继续由 `get_current_admin` 保护。
- `/blog`、`/blog/[id]`、`/notes`、`/notes/[id]`、`/mistakes` 保持公开读取。
- 匿名公开页面不主动请求私有复习或管理数据。

### R1-REQ-03 真实快捷行动

- Dashboard 的写笔记、写博客、录错题/采集、开始复习必须链接到当前存在且权限正确的真实流程。
- 未实现能力不得以可点击成功按钮、假数据或不存在路由呈现。
- 每个行动必须有可访问名称、focus 状态和失败回退。

### R1-REQ-04 局部视觉收敛

- 只在管理工作区内统一蓝白玻璃 token 和高频组件。
- 不允许全仓 `find/sed` 批量替换圆角、背景、边框或 blur。
- 空态、加载态、局部失败、不可用和权限态必须保持可区分。

### R1-REQ-05 创建能力不降级

- note、blog、mistake 的现有字段和安全流程必须保持。
- R1 不以一个通用 `any` 表单替代三类 DTO。
- 错题的一等字段、AI 人工闸门和复习关系不得被压缩为普通 Markdown。
- 博客封面、图片与发布字段不得因入口收敛而丢失。

### R1-REQ-06 兼容路径

- 在完成引用矩阵前不得删除 `write*` 路由。
- 若为 `/workspace` 提供兼容行为，只能重定向到 `/manage/dashboard`，且必须有匿名、管理员和失效会话测试。
- 兼容行为不得绕过 `/manage` 登录体验或后端权限。

### R1-REQ-07 原型处置

- `src/app/workspace/page.tsx` 当前状态必须记录为未跟踪原型。
- 不得覆盖、删除或提交该原型，除非用户在 R1-02 明确选择处置方式。
- 原型中的不存在路由和类型契约错误不能进入正式实现。

## 非功能需求

### R1-NFR-01 可访问性

- 所有 icon-only 操作有 accessible name。
- 键盘可到达主要导航和快捷行动。
- focus ring 可见。
- 支持 reduced motion。
- 文字和交互状态达到可读对比度。

### R1-NFR-02 响应式

- 验证 390×844、1280×800、1440×900。
- 不出现横向溢出、遮挡主操作或移动导航失焦。

### R1-NFR-03 验证

- 实际执行 `npm test` 的定向集合并记录真实通过数。
- 执行 `npx tsc --noEmit`。
- 执行 `npm run build`。
- 在真实浏览器验证匿名、管理员、失效会话和主要行动。
- 若失败源于既有问题，记录首个相关失败，不把它描述为 R1 通过。

### R1-NFR-04 变更纪律

- 保留用户未跟踪与脏工作区内容。
- 每完成一个 R1 task item 立即更新任务清单。
- 不提交、推送、部署或改数据库，除非用户另行明确授权。
