## 数据与权限要求

- 所有私有实体具备 owner 边界；当前默认单管理员，不推导多用户共享。
- 目标公开 API 只返回 `published + public + 未删除` 数据；在兼容期，既有 `/api/notes` 必须继续按其已验证的 `published + hidden=false` 规则返回，直到完成字段映射、契约测试和明确退役决定。
- 创建、更新、删除、上传、AI 写操作、复习提交和设置变更必须由后端管理员依赖保护。
- 文件节点不能绕过业务实体的权限；公开文件必须存在明确的发布关系。
- 版本恢复、删除、迁移转换和人工审核必须可审计、可追踪、可重试或可回滚。
- `AUTH_BYPASS=true` 与 `AUTH_BYPASS_ALLOW=true` 的生产组合必须启动失败。

## 补充验收：契约、文件与迁移

### 公开 API 兼容

1. 每个公开读端点必须有一份“当前路径、目标路径、字段映射、认证、可见性、缓存、退役条件”记录。
2. 任何新 `/api/public/**` 端点必须与其兼容读端点并行通过匿名、管理员、草稿、隐藏、删除和不存在资源测试。
3. 没有已批准退役记录的旧链接、旧页面和旧 API 不得静默删除或改为管理端接口。

### 文件工作区

1. 上传必须验证 MIME、大小和 SHA-256；失败或取消不产生可读正式对象。
2. 每次上传、移动、重命名、删除、恢复、发布和撤销发布都产生操作者、时间、对象 ID、前后位置和结果的审计事件。
3. 移动、重命名、恢复遇到同名或同路径冲突必须显式返回可处理状态，禁止覆盖。
4. 私有附件在匿名、失效会话、非关联资源和已回收状态下均不得读取；公开读取仅来自显式发布关系。
5. 回收站恢复必须在目标冲突、对象缺失和数据库引用不完整时提供可验证错误或恢复路径。

### 迁移执行定义

- `DRY_RUN_READY`：备份、隔离恢复、schema authority、来源清单、映射与冲突规则均通过验证；此前不得运行任何转换程序。
- `dry-run`：只允许向临时隔离目标写入，可随时销毁；不得触碰生产主库、生产附件、旧系统写路径或公开路由。
- `shadow migration`：对生产来源只读、向隔离副本写入，并须取得单独批准。
- `authority switch`：改变正式写入或读取权威来源，须在影子迁移对账、回滚演练和单独批准后执行。

## 迁移门槛

进入 dry-run 前必须证明：

1. 当前数据库和附件有新鲜、可读、可恢复备份。
2. 当前 revision 的数据库与附件能在隔离环境一起恢复。
3. Alembic 与 model/schema 的 authority 已确认，无未解释漂移。
4. 来源清单、哈希、映射、重复、冲突和拒绝规则已冻结。
5. 公开路由、管理员写入、旧写入口和 GitHub 导出方向均有矩阵。

任一项缺失，Migration Gate 保持 `BLOCKED`。

## 完成定义

```text
目标设计完成 != 功能实现完成
功能实现完成 != 浏览器验收完成
浏览器验收完成 != 生产发布完成
生产发布完成 != 迁移切换完成
```

只有阶段证据、剩余风险、回滚方案和用户批准全部齐全，才能将阶段标记为 `COMPLETE / PASS`。
