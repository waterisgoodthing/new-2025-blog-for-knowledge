# Audit Design

## Audit approach

采用“结构证据、文本证据、数据证据、图片证据、渲染证据”五层交叉审查：

1. 结构层：检查 DOCX 可打开性、页数、段落、表格、图片、关系文件及残留占位语。
2. 文本层：检查章节衔接、重复矛盾、措辞风险、事实与能力边界。
3. 数据层：将调查样本数、人数、比例和图表与源 PDF 逐项核对。
4. 图片层：核对图片是否真正嵌入、标题与正文是否对应、色调和可读性是否一致。
5. 渲染层：将 DOCX 转为 PDF/页面图，逐页检查裁切、重叠、分页、模糊、字体缺失和图表缩放。

## Severity model

- `P0`：会导致数据错误、材料失真、关键页面不可读或文件不可用。
- `P1`：会显著影响评审可信度、逻辑完整性或关键论证。
- `P2`：影响专业度、可读性、图文一致性或格式统一。
- `P3`：可选优化，不影响核心结论。

## Evidence rules

- 不根据文件名、占位标题或既有报告推断当前状态。
- 每项问题给出实际位置、现状、影响和建议处理方式。
- 将 `已验证`、`部分验证`、`无法验证` 明确分开。
- 不把设计稿、预测数据、开发中能力或本地演示写成已上线、已验收或真实用户规模。

## Boundaries

- 主审 DOCX 全程只读，不覆盖、不修改、不自动替换图片。
- 本阶段仅生成审查文档与验证记录。
- 修订计划、正文修改、图片替换和重新排版需另行批准。
