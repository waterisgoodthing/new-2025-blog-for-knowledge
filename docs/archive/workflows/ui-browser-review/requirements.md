# Requirements

1. Do not modify business code, database, migrations, test-account permissions, or Git history.
2. Use a real browser and actual rendered pages, not source-only inference.
3. Test accessible major routes at desktop, laptop, and mobile viewports; capture full-page and initial-view screenshots as appropriate.
4. Capture browser console, failed network requests, resource failures, layout overflow, and interaction/state evidence.
5. Create `docs/ui-review/ui-review-report.md`, `page-inventory.md`, `issue-inventory.md`, and `screenshot-index.md`.
6. Each issue must have evidence, severity, route, viewport, reproduction, likely cause, actionable fix, and acceptance criterion.
7. If the user supplies non-production credentials, use them only for local browser login, do not store them in artifacts, and log out after testing.
