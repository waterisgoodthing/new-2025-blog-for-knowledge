## 1. 设计结论

- 管理端采用三组可见名称：今日学习、我的资料、小助手。
- 学习主链使用轻松名称呈现：收进来 -> 待确认 -> 题目册 / 错题本 -> 温习。
- 导航建议为：
  - 今日学习：今天、收进来、待确认、温习。
  - 我的资料：题目册、错题本、学科角、资料袋。
  - 小助手：AI 小助手。
- `设置`保留长期位置，但当前无真实设置能力时不进入一级导航。
- `任务`当前为占位能力，不再作为主要入口。
- `处理记录`保留，作为 AI 小助手内的核心二级入口；底层 `/manage/ai/runs`路由不变。
- 旧 `/manage`仍承载登录和历史内容维护，当前不能直接删除；新工作台不再突出“旧管理面板”。

## 2. 页面职责结论

| 页面 | 下一阶段目标 |
| --- | --- |
| `/manage/dashboard` | 真实待处理事项与常用动作，不显示开发批次或虚构状态 |
| `/manage/capture` | 统一采集入口和状态追踪，承接手工题目录入与错题草稿创建 |
| `/manage/drafts` | 集中审核题目草稿和错题草稿，不承担创建入口 |
| `/manage/questions` | 只管理正式题目 |
| `/manage/mistakes` | 只管理正式错题 |
| `/manage/review` | 只处理到期复习和结果反馈 |
| `/manage/ai` | 只读 AI 小助手：处理记录、模型连接、使用与花费、调用记录 |
| `/manage/jobs` | 从主要入口隐藏，不新增任务能力 |
| `/manage/settings` | 当前隐藏；存在真实设置能力后再恢复入口 |

## 3. 不做事项

- 不修改后端、API、DTO、权限、数据库或 migration。
- 不新增功能、统计接口、队列、worker、设置保存、AI 探针或 Provider 编辑。
- 不改变公开首页的数据边界，不向公开端暴露管理状态。
- 不删除旧 `/manage`中的历史内容、音乐、站点、安全或审计能力。
- 不进行旧数据迁移，不改变正式内容与草稿的领域模型。
- 不用全局通用组件重写所有页面，不引入新的状态库或大型表格依赖。
- 不把开发 Batch 名称换成另一套阶段编号后继续展示。
