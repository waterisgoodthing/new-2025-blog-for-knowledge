# Manage UI Consolidation Requirements

## 1. 状态与目标

- 来源设计：[design.md](./design.md)
- 设计状态：Approved v1.1（包含可爱风文案修订）
- 当前阶段：需求与任务清单编制，等待 `tasks.md`批准
- 目标角色：个人管理员

本项目将现有 `/manage/**` 管理端收束为长期个人学习工作台，同时保持现有 API、权限、数据模型和公开端边界不变。

## 2. 功能需求

### REQ-NAV-001 分组导航

| 项目 | 要求 |
| --- | --- |
| 输入 | 管理员进入任一 `/manage/(workspace)/**` 页面 |
| 处理 | 系统按“今日学习 / 我的资料 / 小助手”分组渲染现有可用页面 |
| 输出 | 只显示 9 个一级入口：今天、收进来、待确认、温习、题目册、错题本、学科角、资料袋、AI 小助手 |
| 失败处理 | 导航配置异常不得渲染虚假入口；页面内容仍应可访问 |
| 验收 | WHEN 管理员查看桌面侧栏 THEN THE SYSTEM SHALL 按批准顺序显示三组、9 个入口，且不显示 Jobs、Settings |

### REQ-NAV-002 父路由激活

| 项目 | 要求 |
| --- | --- |
| 输入 | 当前 pathname，包括一级页和既有详情页 |
| 处理 | 每个导航项使用显式匹配规则判断归属 |
| 输出 | 正确的唯一 `aria-current="page"` 状态 |
| 失败处理 | 未知子路由不应错误激活多个入口 |
| 验收 | WHEN 访问问题、错题、附件详情或 `/manage/ai/runs` THEN THE SYSTEM SHALL 分别激活题库、错题、附件或 AI |

### REQ-NAV-003 移动端抽屉

| 项目 | 要求 |
| --- | --- |
| 输入 | 窄屏管理员打开工作区或触发菜单按钮 |
| 处理 | 顶栏保留当前页名称，菜单按钮打开包含三组导航的抽屉 |
| 输出 | 可键盘操作、可关闭、选中路由后自动关闭的移动导航 |
| 失败处理 | 抽屉关闭后焦点返回菜单按钮；导航失败不让遮罩永久覆盖页面 |
| 验收 | WHEN 在移动视口使用菜单 THEN THE SYSTEM SHALL 不使用横向滚动入口，并正确管理打开、关闭和焦点 |

### REQ-COPY-001 移除开发期文案

| 项目 | 要求 |
| --- | --- |
| 输入 | 日常管理页面的可见标题、说明、徽章、入口和空状态 |
| 处理 | 将开发过程描述替换为稳定业务语言 |
| 输出 | 面向学习任务的页面文案 |
| 失败处理 | 无法确认真实状态时省略状态，不使用占位或虚构结果 |
| 验收 | WHEN 扫描日常管理 UI THEN THE SYSTEM SHALL 不显示 `Batch`、`BATCH`、`MVP`、`占位`、`尚未接入`、`后续启用`、`第一版暂未启用`、`旧管理面板` |

### REQ-COPY-002 温柔可爱的界面语言

| 项目 | 要求 |
| --- | --- |
| 输入 | 用户可见的导航、标题、说明、按钮、状态、空状态、成功与失败提示 |
| 处理 | 按设计词典替换技术性和行政化词语，使用温柔、简短、可爱的中文 |
| 输出 | 例如“今天、收进来、待确认、温习、题目册、错题本、资料袋、AI 小助手、再试一次”等一致文案 |
| 失败处理 | 涉及错误、费用、安全、删除和不可逆操作时优先准确；不确定时使用清楚的普通中文，不强行卖萌 |
| 验收 | WHEN 管理员浏览日常 UI THEN THE SYSTEM SHALL 不直接显示 Dashboard、治理、审计、Provider、Run、Snapshot 等技术词；内部标识、路由和数据值保持不变 |

### REQ-DASH-001 真实总览

| 项目 | 要求 |
| --- | --- |
| 输入 | 现有接口可低成本提供的待处理状态和既有路由 |
| 处理 | 只使用现有轻量请求组织待处理事项与常用入口 |
| 输出 | 可继续采集、审核、复习和内容管理的总览 |
| 失败处理 | 请求失败显示未知或局部错误，不显示为 `0`，且不阻断主要入口 |
| 验收 | WHEN 总览无法可靠取得数量 THEN THE SYSTEM SHALL 省略数字徽章；不得新增统计接口或拉取全量列表计数 |

### REQ-CAP-001 三种采集方式

| 项目 | 要求 |
| --- | --- |
| 输入 | 管理员选择上传图片、手工录入题目或从题库记录错题 |
| 处理 | 选择后只展开对应既有工作区和字段 |
| 输出 | 单一采集入口下的三个清晰流程，现有提交行为保持不变 |
| 失败处理 | 某种方式加载失败只影响对应工作区，并提供就地错误或重试 |
| 验收 | WHEN 打开采集页 THEN THE SYSTEM SHALL 先显示三种方式，不把三套字段合并成一个大型表单 |

### REQ-DRAFT-001 统一审核中心

| 项目 | 要求 |
| --- | --- |
| 输入 | 现有题目草稿与错题草稿列表数据 |
| 处理 | 在单一列表中聚合展示，并提供“全部 / 题目草稿 / 错题草稿”筛选 |
| 输出 | 每行展示内容类型、摘要、来源、状态、创建时间和查看审核入口 |
| 失败处理 | 一类草稿加载失败不得伪装为空；应显示局部错误并允许重试 |
| 验收 | WHEN 查看待审核页 THEN THE SYSTEM SHALL 不显示创建表单，也不在首屏堆叠两套完整列表 |

### REQ-QUESTION-001 正式题库边界

| 项目 | 要求 |
| --- | --- |
| 输入 | 现有正式题目数据 |
| 处理 | 按既有状态筛选并提供正式题目详情入口 |
| 输出 | 只承担正式题目管理的题库页 |
| 失败处理 | 无数据和请求失败必须使用不同状态，不引导到错误的创建位置 |
| 验收 | WHEN 查看题库 THEN THE SYSTEM SHALL 不出现草稿创建或草稿审核模块 |

### REQ-MISTAKE-001 正式错题边界

| 项目 | 要求 |
| --- | --- |
| 输入 | 现有正式错题数据 |
| 处理 | 展示、筛选并进入正式错题详情 |
| 输出 | 只承担正式错题管理的错题页 |
| 失败处理 | 无数据和请求失败必须区分；不得回退展示草稿创建表单 |
| 验收 | WHEN 查看错题页 THEN THE SYSTEM SHALL 不出现错题草稿创建或待审核草稿列表 |

### REQ-REVIEW-001 今日复习工作区

| 项目 | 要求 |
| --- | --- |
| 输入 | 现有到期复习项和人工评分 |
| 处理 | 保留到期项、评分提交、历史记录和结果反馈 |
| 输出 | 单一焦点的今日复习页面 |
| 失败处理 | 提交失败保留当前内容与评分上下文，并允许重试 |
| 验收 | WHEN 管理员完成评分 THEN THE SYSTEM SHALL 给出稳定就地反馈，不改变现有复习 API 或排期规则 |

### REQ-AI-001 只读 AI 小助手

| 项目 | 要求 |
| --- | --- |
| 输入 | 现有 Run 审计、Provider 状态、健康、用量费用、统计和技术日志数据 |
| 处理 | 按处理记录、模型连接、使用与花费、调用记录组织页面 |
| 输出 | 可进入 `/manage/ai/runs` 的只读 AI 小助手页面 |
| 失败处理 | 单个区块失败局部呈现；未知费用显示“还没有费用记录，不代表 0” |
| 验收 | WHEN 查看 AI 小助手 THEN THE SYSTEM SHALL 不提供在线配置、主动探针或其他新写操作，且技术名词有易懂中文替代 |

### REQ-AI-002 AI 敏感信息边界

| 项目 | 要求 |
| --- | --- |
| 输入 | 现有 AI 管理响应和错误数据 |
| 处理 | 只渲染批准的只读摘要字段 |
| 输出 | 不含敏感数据或原始输入的治理信息 |
| 失败处理 | 无法安全归类的字段默认不展示 |
| 验收 | WHEN 检查页面与前端响应使用 THEN THE SYSTEM SHALL 不展示 API key、authorization、cookie、secret、token、prompt、input summary、replay input 或原始 Provider 错误正文 |

### REQ-COMP-001 管理端组件规范

| 项目 | 要求 |
| --- | --- |
| 输入 | 各管理页重复的页面头、面板、状态、空态、表格和表单外壳 |
| 处理 | 抽取只负责表现与交互骨架的 manage-scoped 组件 |
| 输出 | 一致的管理端 PageHeader、Panel、EmptyState、StatusBadge、组合式 Table 和 FormPanel |
| 失败处理 | 某页面无法适配时保留局部实现，不扩张组件 API 迁就单例 |
| 验收 | WHEN 复用管理组件 THEN THE SYSTEM SHALL 不封装 API、DTO 或业务提交逻辑，也不新增大型表格依赖 |

### REQ-COMP-002 显式状态映射

| 项目 | 要求 |
| --- | --- |
| 输入 | 各领域业务状态 |
| 处理 | 页面显式映射到 `neutral/info/success/warning/danger`语义 tone |
| 输出 | 一致且可审查的状态徽章 |
| 失败处理 | 未映射状态使用中性样式并保留可读标签，不猜测成功或失败 |
| 验收 | WHEN 渲染状态 THEN THE SYSTEM SHALL 不让 StatusBadge 内部理解领域枚举或根据状态字符串猜颜色 |

### REQ-STATE-001 页面反馈完整性

| 项目 | 要求 |
| --- | --- |
| 输入 | loading、empty、filtered-empty、error、busy、success 状态 |
| 处理 | 使用统一但紧凑的反馈模式，并保持容器尺寸稳定 |
| 输出 | 清晰的页面内状态；toast 仅作为补充 |
| 失败处理 | 错误状态提供重试或恢复路径，不被空状态覆盖 |
| 验收 | WHEN 任一列表或表单进入上述状态 THEN THE SYSTEM SHALL 有明确反馈且不造成按钮宽度或主体布局跳动 |

### REQ-PUBLIC-001 公开端边界

| 项目 | 要求 |
| --- | --- |
| 输入 | 未登录访客访问公开首页和公开内容页面 |
| 处理 | 继续只加载公开内容与公开体验所需信息 |
| 输出 | 不包含管理 Dashboard、AI、任务队列或私有复习详情的公开页面 |
| 失败处理 | 管理接口失败不得在公开页面产生明显错误或反复 401/403 噪音 |
| 验收 | WHEN 未登录访问公开端 THEN THE SYSTEM SHALL 不渲染或请求本任务新增的管理信息 |

### REQ-COMPAT-001 路由与能力兼容

| 项目 | 要求 |
| --- | --- |
| 输入 | 旧 `/manage`、Jobs、Settings 和现有详情 URL 的直接访问 |
| 处理 | 隐藏主要入口但不在本阶段删除路由或历史能力 |
| 输出 | 旧 `/manage`登录和未迁移能力仍可使用，现有详情链接仍有效 |
| 失败处理 | 发现路由依赖无法兼容时停止对应删除动作并记录独立需求 |
| 验收 | WHEN 通过旧链接直接访问 THEN THE SYSTEM SHALL 不因本次 UI 收束产生 404 或功能删除 |

## 3. 非功能需求

| 编号 | 要求 | 验收条件 |
| --- | --- | --- |
| NFR-001 | 权限不变 | 所有 workspace 页面继续由 `AuthGate`保护，后端管理员权限无修改 |
| NFR-002 | 数据契约不变 | 不修改 API、DTO、数据库、migration 或数据模型 |
| NFR-003 | 响应式 | 桌面与移动端无导航遮挡、文本溢出、控件跳动或无意义大面积空白 |
| NFR-004 | 可访问性 | 图标按钮有可访问名称；抽屉有焦点管理；键盘顺序合理；200% 缩放仍可操作 |
| NFR-005 | 性能 | 不新增全量列表计数、重复轮询或 Dashboard 聚合请求 |
| NFR-006 | 可维护性 | 组件保持 manage-scoped、小接口、无业务请求，状态映射显式 |
| NFR-007 | 视觉一致性 | 保留浅蓝绿色与低压力感；管理内容面板不超过 8px 圆角，数据主体保持足够对比度 |
| NFR-008 | 验证 | TypeScript 检查通过；构建敏感变更通过构建；桌面、移动与关键状态完成浏览器验收 |

## 4. 范围边界

本阶段不得：

- 修改 `backend/`、API、DTO、权限、数据库或 migration。
- 新增统计接口、队列、worker、设置保存、AI 主动探针或 Provider 编辑。
- 删除旧 `/manage`、Jobs、Settings 或现有详情路由。
- 迁移旧数据或改变题目、错题、草稿、复习的领域模型。
- 改变公开首页或公开内容页的产品定位。
- 引入新的状态管理库或大型表格依赖。

## 5. 批准门

本文档与 [tasks.md](./tasks.md) 只定义下一阶段工作。必须获得用户对 `tasks.md` 的明确批准后，才能修改任何 `src/` 文件。
