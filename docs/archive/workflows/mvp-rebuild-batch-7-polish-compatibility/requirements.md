# 需求文档：Batch 7 体验收口、旧路由兼容、数据质量

## 背景与角色

MVP Rebuild 已完成管理工作区壳层、科目/知识点、题目草稿与题库、错题与复习、附件基础、
AI/OCR 占位等批次。进入第一版收口前，需要确认新旧入口不会互相污染、公开读取边界仍然正确、
管理端核心流程具备基本的空状态/错误状态/危险操作确认，并留下可由本地环境复现的试运行说明。

主要角色：

- 个人管理员：使用 `/manage/*` 完成草稿、题目、错题、复习、附件等管理操作。
- 未登录访客：继续公开读取博客、笔记和已发布未隐藏的错题内容。
- 后续维护者：根据本批记录判断第一版是否可本地试运行，以及哪些风险进入下一轮需求。

## 核心问题

1. 旧入口与新管理工作区并存，用户可能从 `/write-mistake`、`/write-note` 等旧路由进入不一致流程。
2. 公开 `/mistakes`、`/notes`、`/blog` 必须保持可读，不能因为管理端状态、复习统计或管理员操作而污染。
3. 管理端第一版页面可能存在空状态、加载状态、错误状态、基础校验和危险操作确认不足。
4. 数据质量需要被检查和记录，但不得自动删除、迁移或“修正”旧数据。
5. 本地试运行步骤需要可复现，不能只用 build 成功替代真实使用验收。

## 功能需求

### REQ-B7-01 旧入口兼容策略

- 输入：用户访问旧 `/write-mistake`、`/write-mistake/[slug]`、`/write-note`、`/write-note/[slug]`。
- 处理：审计当前行为，并为 Batch 7 tasks 列出轻量兼容方案：保留、提示迁移、重定向或延后。
- 输出：旧入口处理方式清楚，不破坏仍需保留的原流程。
- 失败：不得在未审批实现前修改旧路由；不得把公开页或原写作流强制封死。
- 验收：`tasks.md` 中列出每个旧入口的目标行为、文件范围、验证方式和停止条件。

### REQ-B7-02 公开读取边界

- 输入：匿名用户访问 `/mistakes`、`/notes`、`/notes/[slug]`、`/blog`、`/blog/[slug]`。
- 处理：审计公开页面是否请求管理员 API、展示管理按钮、暴露复习/AI/上传操作或因 401/403 产生错误噪音。
- 输出：公开页保持公开读取，只展示已发布且未隐藏内容；管理入口仅在登录态或管理区出现。
- 失败：不得给公开页机械加 `AuthGate`；不得把管理员接口失败显示成公开页错误。
- 验收：验证记录列明公开页检查范围、API 调用边界和是否存在待修复项。

### REQ-B7-03 管理端体验状态收口

- 输入：管理员访问 Batch 2–6 已完成的 `/manage/*` MVP 页面。
- 处理：审计并补齐必要的 empty、loading、error state；错误必须可读，不能伪装成成功。
- 输出：用户在无数据、加载中、失败时都能理解当前状态和下一步。
- 失败：不得引入新状态库；不得用假数据、假成功 toast 或静默吞错。
- 验收：每个被纳入实现的页面有明确状态清单和浏览器验证。

### REQ-B7-04 基础表单校验与危险操作确认

- 输入：管理员进行创建、编辑、删除、归档、拒绝、转换、关联、上传等 MVP 范围操作。
- 处理：检查必填字段、格式、空白输入、危险操作确认和错误提示。
- 输出：明显无效输入在前端或后端有清楚反馈；危险操作有明确确认文案。
- 失败：不得新增完整练习系统、统计系统或复杂工作流；不得仅靠前端隐藏保护写操作。
- 验收：tasks 明确列出纳入本批的小范围表单和操作，执行后用浏览器/API/测试记录验证。

### REQ-B7-05 首页入口与明显死链检查

- 输入：首页学习轻卡、管理侧栏、dashboard、MVP 范围内的主要导航链接。
- 处理：检查链接是否指向存在页面；首页学习轻卡应指向 `/manage/drafts` 与 `/manage/review` 等已批准管理入口。
- 输出：MVP 主链路没有明显 404 或误导性入口。
- 失败：不得借机新增营销页、公开站大重做或新的大型导航系统。
- 验收：记录链接检查范围、结果和任何延后项。

### REQ-B7-06 数据质量检查与记录

- 输入：Batch 2–5 相关表、关键字段和现有旧数据。
- 处理：只读检查科目、知识点、草稿、题目、错题、复习、附件与关联的基本完整性。
- 输出：形成数据质量结果、异常样本、影响评估和后续建议。
- 失败：不得自动删除、自动迁移、自动合并或批量修复旧数据。
- 验收：`validation.md` 或数据质量报告记录查询范围、结论、风险和是否进入下一轮需求。

### REQ-B7-07 本地试运行说明

- 输入：新维护者或用户在本地准备运行第一版 MVP。
- 处理：整理启动前置、环境变量、数据库迁移、前后端启动、登录、核心路径试跑、常见失败排查。
- 输出：本地试运行说明可复现，且不包含生产绕过认证建议。
- 失败：不得加入云部署、对象存储或生产发布流程。
- 验收：说明文档经过命令或人工步骤核对，失败项记录为风险。

## 非功能需求

- 安全：公开读取和管理员写入边界不变；不依赖 `AUTH_BYPASS` 通过权限验收。
- 可审查：Batch 7 diff 必须小范围、按任务拆分，不混入新大型功能。
- 可回退：旧入口兼容不得删除旧数据或破坏原流程。
- 可验证：不能以 build 成功替代浏览器、API、权限和数据质量证据。
- 可维护：只沿用现有 Zustand/SWR/API client/组件模式，不引入新状态库或大依赖。

## 明确不做

- AI、OCR、Capture Router、多模型路由、Prompt 管理或调用记录持久化。
- BKT、完整练习系统、统计报告、搜索索引或复杂队列。
- 对象存储、R2、S3、云部署、生产发布、CDN 或云端数据迁移。
- 公开站大重做、设计系统重建、复杂兼容层。
- 删除旧数据、自动迁移旧错题、自动批量修复历史内容。

## 总体验收

Batch 7 只有在以下条件同时满足后才能进入“等待用户验收”：旧入口兼容策略执行结果清楚；
公开读取页未被管理端污染；管理端核心页面具备基础状态、校验与确认；明显死链已检查；
数据质量只读结果已记录；本地试运行说明可复现；未新增禁止的大型能力；用户明确确认后才可归档第一版。
