# 需求文档：Batch 0 文档冻结

## 1. 背景

当前架构文档描述了包含 AI、OCR、BKT、练习、搜索、统计等能力的长期蓝图，但 MVP
已被拆成 8 个严格顺序批次。如果没有独立、权威的 MVP 范围文档，后续实现可能将
长期蓝图误解为第一版交付范围。

## 2. 使用者

- 项目所有者：确认冻结范围与每批验收。
- 后续 Codex：判断当前批允许与禁止内容。
- 外部执行代理：理解候选模型不等于已经落地。

## 3. 功能需求

### REQ-B0-01：MVP 权威范围

- 输入：8 批 spec、现有架构蓝图和仓库权限规则。
- 处理：创建 `docs/architecture/mvp-scope.md`。
- 输出：手工学习闭环、批次边界、候选页面、候选表、暂缓项和变更门禁。
- 失败处理：有冲突时标注“待确认”，不替未来批次做迁移决定。
- 验收：文档可独立回答第一版做什么、不做什么、按什么顺序做。

### REQ-B0-02：Review MVP 与长期算法分离

- 输入：现有 `review-system.md`。
- 处理：将 MVP 简单复习与 BKT、掌握度、复杂容量控制分层。
- 输出：MVP 只要求 review item、review record、简单间隔或简单 SM-2。
- 失败处理：不能确认的算法参数保留为长期建议，不写成第一版要求。
- 验收：MVP 复习提交不再强制写 mastery event。

### REQ-B0-03：首页与管理台密度冻结

- 输入：现有 UI 目标和 Batch 1 spec。
- 处理：记录 `/` 低密度、`/manage` 高密度的职责边界。
- 输出：后续 UI 不会把公开首页改成 Dashboard。
- 失败处理：具体视觉或组件实现推迟到 Batch 1。
- 验收：文档同时说明公开读取和管理员保护边界。

### REQ-B0-04：候选模型状态透明

- 输入：未来 question、mistake、review、attachment 表设计与当前 Note 架构。
- 处理：按批次列出候选表，并注明待设计、待迁移、未实现。
- 输出：不存在“文档写了表名就代表表已存在”的误解。
- 失败处理：模型冲突进入对应批次 handoff，不在 Batch 0 解决。
- 验收：明确当前错题是 `Note(type="mistake")`，不存在已确认的独立
  `/api/mistakes` 合同。

### REQ-B0-05：批次门禁

- 输入：Batch 0 至 Batch 7。
- 处理：记录依赖、进入条件和用户确认要求。
- 输出：后续不能跳批或一次性实现全量系统。
- 失败处理：缺少当前批验收或用户确认时停止。
- 验收：8 批顺序、各批核心目标和门禁均可核对。

## 4. 非功能需求

- 一致性：`mvp-scope.md`、架构首页和 review 文档不互相矛盾。
- 可审查：长期目标、MVP 候选、当前实现三种状态用词明确。
- 安全性：公开读取与管理员写入边界不因规划改变。
- 可维护性：不复制全部长期架构，只提供范围入口和明确链接。
- 可追踪：每项修改和验证记录在本 workflow。

## 5. 本批不做

- 不修改 `src/`、`backend/`、样式、配置、依赖、迁移或数据。
- 不创建页面、API、数据库表或模型。
- 不执行 Batch 1 至 Batch 7。
- 不决定独立 question/mistake 模型的最终迁移方案。
- 不运行安装、服务、构建、迁移或全项目格式化。

## 6. 验收标准

1. `docs/architecture/mvp-scope.md` 存在并覆盖全部冻结项。
2. `review-system.md` 明确 BKT、mastery events、复杂容量控制后置。
3. 架构首页链接 MVP 范围，并不再把 OCR/Capture 或完整练习写成第一版承诺。
4. `/` 低密度、`/manage` 高密度原则明确。
5. 8 批顺序、候选页面、候选表和暂缓项清楚。
6. 当前 `Note(type="mistake")` 与未来独立模型的关系标为待确认。
7. Batch 0 checklist 与 handoff 准确填写。
8. 验证证明只修改了本批允许的文档。
