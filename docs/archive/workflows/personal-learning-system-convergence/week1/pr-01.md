# PR-01 — Runtime Smoke（R31 / D12）设计与证据

> 风险：MEDIUM ｜ Owner：Senior DevOps/SRE（子代理）｜ 评审：Principal Technical Reviewer（独立子代理）｜ 验证：Senior QA/SDET（独立子代理）

## 1. 设计（2026-09-08 定版）

### 1.1 交付物

1. `scripts/runtime-smoke.mjs` — 库 + CLI（D12 步骤 1–6）：
   - `GET <frontend-url>/` → 必须 2xx；
   - 解析 HTML `<script src>` 与 `<link href>`（相对路径基于页面 URL 解析；去重；跳过 `data:`/`blob:`/`javascript:`/`mailto:`/纯锚点）；
   - 逐个 GET 引用资产，要求 2xx（10s 超时/请求，并发 6，超时/网络错误计 failed）；
   - `GET <frontend-url>/notes` → 200；
   - `GET <api-health-url>` → 200（默认 `http://127.0.0.1:8001/api/health`，T-00b 定版 smoke 端口 8001，8000 被常驻进程占用）；
   - 输出人类可读逐项结果 + 一行 JSON 汇总（`referenced/ok/failed` 计数）；
   - 任何失败（页面/资产/健康）→ **exit 1**（阻断发布）。
2. CLI 参数：`--frontend-url`（默认 `http://localhost:8787`）、`--api-health-url`（默认 `http://127.0.0.1:8001/api/health`）、`--timeout`（默认 10000ms）、`--concurrency`（默认 6）。
2a. **提取边界定版（2026-09-08 拓扑实测后修订）**：`<link rel="preconnect">` 与 `rel="dns-prefetch"` 为连接提示，浏览器从不 GET 该 URL（实测其对根路径 GET 恒 404，属必然误报），**不计入资产 fetch 集**；`stylesheet`/`icon`/`preload`/`modulepreload` 等真实加载资源仍逐个 GET。依据 R31-4："smoke 只证明某次响应引用的资源可访问"。
3. `scripts/runtime-smoke.test.mjs` — `node:test` 单测（沿 `predeploy-gates.test.mjs` 模式）：资产提取纯函数、去重/跳过规则、汇总与退出码判定、mock fetch 的 runSmoke 集成（资产 404 → exit 1；全绿 → exit 0）。
4. `package.json` 增加 `"smoke": "node scripts/runtime-smoke.mjs"`。
5. `docs/public-deploy-runbook.md`：将"script lands with PR-01"的临时说明替换为脚本实际用法（pre-deploy 本地拓扑 + post-deploy 生产 URL 两段）；保留用户既有全部内容。

### 1.2 拓扑事实源（T-00b，phase-0-evidence §3）

- 前端 production 工件：`npm run build:cf` → `npm run preview`（workerd，**:8787**）；禁止 `next dev`/`next start` 冒充。
- backend：`backend/.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8001`（workdir backend/，DATABASE_URL 指向一次性 scratch 库）；`alembic upgrade head` **先于**启动；seed SQL 见 phase-0-evidence §3.5。
- build:cf 首跑 flake（R-T00-3）：失败可重试一次再判 FAIL。
- 本地 preview 页面数据请求指向生产 API（构建期内联），smoke 只验证资产完整性/页面壳；`/api/health` 探针独立打本地 backend。
