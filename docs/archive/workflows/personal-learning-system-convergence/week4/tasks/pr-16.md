## Objective

Implement graduated delay-based login throttling on both account and IP dimensions to mitigate brute-force attacks while maintaining availability for legitimate users.

## Scope

**In scope:**
- Dual-dimension failure tracking (account + IP)
- Graduated delay schedule (configurable)
- Account counter reset on successful login
- IP counter time-based decay
- Configuration in `backend/app/config.py`

**Out of scope:**
- Permanent account lockout
- CAPTCHA challenges
- Geographic/device-based anomaly detection
- Complex fraud detection (velocity checks, behavior profiling)
- Multi-factor enforcement

## Throttling Strategy (W4-D04)

**Dimensions:**
- **Account-level**: track failures per `username` or `email` (whichever is used in login request)
- **IP-level**: track failures per `request.client.host`

**Delay schedule (default, configurable):**
- Attempts 1-3: no delay (immediate response)
- Attempt 4: 2 seconds delay
- Attempt 5: 5 seconds delay
- Attempt 6+: 15 seconds delay

**Reset conditions:**
- Account counter: reset to 0 on successful login
- IP counter: time-based decay (e.g., 1-hour TTL per entry)

**Priority:** Availability > sophisticated abuse prevention. Single-user project accepts some attack surface to avoid locking out legitimate users.

### 2. Failure tracker

Choose storage mechanism (document choice):

**Option A: In-memory dict (simpler, acceptable for single-instance deployment)**
```python
# backend/app/services/throttle_service.py
from datetime import datetime, timedelta
from typing import Dict, Tuple

# Format: {key: (failure_count, last_failure_time)}
_account_failures: Dict[str, Tuple[int, datetime]] = {}
_ip_failures: Dict[str, Tuple[int, datetime]] = {}

def record_failure(account: str | None, ip: str):
    now = datetime.utcnow()
    if account:
        count, _ = _account_failures.get(account, (0, now))
        _account_failures[account] = (count + 1, now)
    if ip:
        count, _ = _ip_failures.get(ip, (0, now))
        _ip_failures[ip] = (count + 1, now)

def record_success(account: str):
    _account_failures.pop(account, None)  # Reset account counter

def get_required_delay(account: str | None, ip: str, config) -> float:
    now = datetime.utcnow()
    delays = [float(d) for d in config.LOGIN_THROTTLE_DELAYS.split(",")]
    
    # Check account failures
    account_delay = 0.0
    if account and account in _account_failures:
        count, _ = _account_failures[account]
        if count > config.LOGIN_THROTTLE_WARN_THRESHOLD:
            delay_index = min(count - config.LOGIN_THROTTLE_WARN_THRESHOLD - 1, len(delays) - 1)
            account_delay = delays[delay_index]
    
    # Check IP failures (with TTL decay)
    ip_delay = 0.0
    if ip and ip in _ip_failures:
        count, last_fail = _ip_failures[ip]
        age = (now - last_fail).total_seconds()
        if age < config.LOGIN_THROTTLE_IP_TTL_SECONDS:
            if count > config.LOGIN_THROTTLE_WARN_THRESHOLD:
                delay_index = min(count - config.LOGIN_THROTTLE_WARN_THRESHOLD - 1, len(delays) - 1)
                ip_delay = delays[delay_index]
        else:
            del _ip_failures[ip]  # Expired, clean up
    
    return max(account_delay, ip_delay)  # Apply stricter of the two
```

### 3. Router integration

Update `backend/app/routers/auth.py` (or wherever login endpoint lives):

```python
from app.services.throttle_service import record_failure, record_success, get_required_delay
import asyncio

@router.post("/login")
async def login(
    credentials: LoginRequest,
    request: Request,
    db: Session = Depends(get_db),
    config: Settings = Depends(get_settings)
):
    if config.LOGIN_THROTTLE_ENABLED:
        # Check if delay is required BEFORE attempting auth
        account = credentials.username or credentials.email
        ip = request.client.host
        delay = get_required_delay(account, ip, config)
        if delay > 0:
            await asyncio.sleep(delay)
    
    # Attempt authentication
    user = authenticate_user(db, credentials)
    
    if not user:
        # Failed login
        if config.LOGIN_THROTTLE_ENABLED:
            record_failure(account, ip)
        raise HTTPException(status_code=401, detail="Invalid credentials")
    
    # Successful login
    if config.LOGIN_THROTTLE_ENABLED:
        record_success(account)
    
    # ... create session, return token, etc.
    return {"access_token": "..."}
```

## Acceptance Criteria

### Configuration
- [ ] All throttle settings in `backend/app/config.py`
- [ ] Can be overridden via `.env` (for local development or testing)
- [ ] Delay schedule is comma-separated string, parsed as list of floats
- [ ] TTL and thresholds are integer seconds

### Functionality
- [ ] Account-level failures tracked; counter increments on each failed login
- [ ] IP-level failures tracked with TTL decay
- [ ] Graduated delays applied: 0s → 0s → 0s → 2s → 5s → 15s (for attempts 1-6+)
- [ ] Successful login resets account counter to 0
- [ ] IP counter expires after TTL (default 1 hour)
- [ ] Delay is `max(account_delay, ip_delay)` (stricter dimension wins)
- [ ] Delay happens BEFORE auth attempt (protects DB/CPU from spam)

- [ ] Error messages do not leak "you're being throttled" (same 401 response)
- [ ] Logs contain failure counts at WARN level for monitoring
- [ ] No permanent lockout (users can always retry after delay)
