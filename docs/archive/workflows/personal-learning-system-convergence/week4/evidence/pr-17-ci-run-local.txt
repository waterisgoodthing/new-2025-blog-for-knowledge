Root cause (blocking local full-stack auth):
  admin_session is SameSite=Lax with Path=/api. In the local topology the preview origin is
  http://localhost:8787 while the API is http://api.localhost:8001 — Chromium treats these as
  cross-site, so the Lax cookie is not sent on the subsequent credentialed fetch, and the
  workspace stays unauthenticated.
  The CI topology avoids this by serving/pointing at http://app.ci.test:8787 and
  http://api.ci.test:8001, which share the registrable domain ci.test (same-site); the workflow
  maps both to 127.0.0.1 via /etc/hosts and sets ALLOWED_ORIGINS=http://app.ci.test:8787.
  That CI path could not be exercised here: no passwordless sudo to edit /etc/hosts, and the
  sandbox resolver sends *.ci.test to 198.18.1.16 (not loopback).
