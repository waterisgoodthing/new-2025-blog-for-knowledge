Interpretation
--------------
- A target-linked call (capture_recognition with capture_id) stores target_type
  and target_id on the ai_runs row.
- A creation-type run created with NULL target (capture_draft) is backfilled by
  `backfill_ai_run_target`, moving linked_runs from 1/3 to 2/3; the row now
  shows target_type=Mistake with the new entity id.
- The abandoned run (mistake_question_draft) still has NULL target after the
  backfill call and is reported as the remaining unlinked row — the documented
  valid terminal state.
- Integration status: `backfill_ai_run_target` is implemented and exercised here
  and in tests/test_ai_governance.py, but NO production confirmation endpoint
  calls it yet (NOT_YET_WIRED; see docs/architecture/ai-governance.md).
