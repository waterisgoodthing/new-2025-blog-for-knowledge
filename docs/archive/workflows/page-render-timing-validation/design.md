# 页面渲染时效验证设计

## 测量边界

本验证测量真实浏览器中的页面可用时间，而不是仅使用 HTTP 响应时间或 Lighthouse 推测值。

| 场景 | 起点 | 终点 | 主要结果 |
| --- | --- | --- | --- |
| 匿名公开页 | 浏览器开始导航至 `/notes` | 首屏主内容已落地，且不再处于加载骨架/加载文案状态 | navigation 指标、content-ready 时间 |
| 管理员登录后页面 | 在 `/manage` 点击登录提交 | 正常会话建立后，管理页的主内容处于已结算状态 | login-submit-to-ready 时间、导航/API 分解 |

“主内容已落地”必须由该页面的真实 DOM 状态确认：有内容项，或有明确的空态/错误态；仅出现页面壳、标题或骨架不算完成。

## 运行拓扑

```text
干净浏览器上下文
      |
      v
隔离 Next.js 进程 -> 隔离 FastAPI 进程 -> 隔离测试数据库
      |                         |
      |                         +-> 仅供验证的临时管理员（正常登录）
      v
agent-browser + 浏览器 Performance API + 网络资源记录
```

- 不使用生产站点、真实管理员账户或认证绕过；
- `AUTH_BYPASS` 与 `AUTH_BYPASS_ALLOW` 必须保持关闭；
- 临时管理员只在隔离数据库中创建，并在验证结束后禁用/清理；
- 前端、后端端口及输出目录须与既有进程隔离，避免复用 `.next` 产物或污染开发会话。

## 采集方法

每个场景至少采集 5 次冷启动浏览器上下文。若环境稳定，可额外记录 5 次同会话重复访问作为“热访问”对照；两者不得混合计算。

每次采集记录：

1. 浏览器 Navigation Timing：TTFB、`domContentLoadedEventEnd`、`loadEventEnd`；
2. 从 `navigationStart` 到 content-ready 判定成立的实际时长；
3. 登录场景从提交动作开始到管理页 content-ready 的实际时长；
4. 关键 API 与静态资源的耗时、状态码和失败项；
5. 页面控制台错误、请求失败、认证重定向或重复请求。

结果以中位数与最大值呈现。样本不足、页面未稳定、鉴权失败、主 API 失败或环境不隔离时，必须标记为 `BLOCKED` 或 `INVALID`，不能输出误导性的性能结论。

## 不在范围内

- 不修改 React 组件、Skeleton、缓存策略、接口、认证或样式；
- 不设定未经现状基线支持的性能 SLA；
- 不把本地结果外推为 CDN、真实公网设备或生产数据库性能；
- 不使用真实用户内容或真实管理员凭据。
