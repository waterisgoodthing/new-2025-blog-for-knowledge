# Batch 6：AI / OCR 预留接口与占位

## 目标

不接入真实自动化，只把未来 AI、OCR 和任务观察入口留在管理端，并确保主流程完全
不依赖这些占位能力。

## 背景

MVP 的价值来自稳定的手工学习闭环。过早接入模型、OCR、多模型路由或后台队列会
扩大依赖和失败面，因此本批只提供诚实、无副作用的占位状态。

## 任务范围

1. `/manage/ai`、`/manage/jobs`、`/manage/settings` 提供占位页面。
2. 附件详情显示“OCR 第一版暂未启用”状态。
3. AI 控制台展示模型、Prompt、调用记录的非交互占位结构。
4. 所有文案明确能力尚未启用。
5. 验证题目、错题、附件和复习主流程不调用 AI/OCR。
6. 若复用既有 AI 路由或组件，只能展示已保存结果，不得开放新的未鉴权操作。

## 允许修改范围

- 本批对应 workflow 文档。
- `/manage/ai`、`/manage/jobs`、`/manage/settings` 路由与专属占位组件。
- 附件详情中的 OCR 状态区域。
- 管理导航及直接相关前端测试、验证材料。

本批不允许新增真实 AI/OCR 后端合同、模型、迁移、队列或外部服务配置。

## 禁止事项

- 不接 Qwen、DeepSeek、Kimi 或 PaddleOCR。
- 不接 Capture Router 或多模型路由。
- 不建完整 `ai_model_profiles`、`ai_runs` 或 `ocr_jobs`。
- 不做真实后台任务队列。
- 不加入可触发真实调用的按钮、请求或假成功状态。
- 不让未登录访客获得 AI 分析、重新生成或 OCR 操作。

## 涉及页面

- `/manage/ai`
- `/manage/jobs`
- `/manage/settings`
- `/manage/attachments/[id]`

## 涉及数据表

无。本批不得新增 AI、OCR 或任务队列表。

## 验收标准

1. 用户能清楚知道 AI/OCR 是后续阶段。
2. 当前主流程不依赖 AI/OCR。
3. 没有未完成或隐藏的真实调用逻辑。
4. 占位页面可访问且不报错。
5. 占位状态不会虚构调用记录或成功结果。
6. 管理页面访问保护与公开页面权限边界保持正确。

## 非目标

任何模型调用、OCR、Prompt 管理、调用日志持久化、任务队列或自动分流。

## 完成后 handoff 要求

记录占位页面、明确未启用的能力、证明主流程无依赖的检查、权限验证、风险和 Batch 7
前置条件，并等待用户确认。
