# Batch 2：科目 / 知识点基础

## 目标

建立学习系统的分类底座，使后续题目能够选择科目、章节和知识点。

## 背景

题目草稿、题库和错题流程需要稳定的分类数据。该底座必须先于题目业务建立，
但不扩展为知识图谱或掌握度系统。

## 任务范围

1. 新增 subject CRUD。
2. 新增 chapter CRUD。
3. 新增 knowledge point CRUD。
4. 支持知识点绑定 subject / chapter。
5. 支持基础知识点列表与详情。
6. 提供后续题目绑定知识点所需的选择器基础。
7. 在本批设计阶段核对现有后端、前端 API 和迁移约定后再确定最终命名与合同。

## 允许修改范围

- 本批对应 workflow 文档。
- 经批准的数据模型、Pydantic schema、service、thin router 与 Alembic migration。
- 对应 `src/lib/api/` 类型化客户端。
- `/manage/subjects` 与知识点相关管理页面和路由专属组件。
- 直接相关测试、导航与验证材料。

具体文件与迁移策略必须先写入本批 tasks 并获用户批准。

## 禁止事项

- 不做知识图谱或关系可视化。
- 不做 AI 知识点建议。
- 不做 BKT 掌握度。
- 不做复杂统计。
- 不提前实现题目、错题、附件或复习业务。

## 涉及页面

- `/manage/subjects`
- `/manage/subjects/[id]`
- `/manage/knowledge-points/[id]`

## 涉及数据表

- `subjects`
- `chapters`
- `knowledge_points`
- `knowledge_point_links`
- 可选：`tags`、`taggings`，仅在设计证明为本批必需且重新获批时纳入。

## 验收标准

1. 可以创建、读取、更新和删除科目。
2. 可以创建、读取、更新和删除章节。
3. 可以创建、读取、更新和删除知识点。
4. 知识点可以归属科目和章节。
5. 后续题目界面能够复用选择器选择这些知识点。
6. 前后端合同与迁移一致，管理员写入保护有效。
7. 空状态、错误状态和基础校验有验证记录。

## 非目标

知识图谱、BKT、AI 分类、题目业务、复杂标签系统和统计报表。

## 完成后 handoff 要求

列出最终数据合同、迁移、API、页面、测试证据、未完成项、风险和 Batch 3 前置条件，
并等待用户明确确认。
